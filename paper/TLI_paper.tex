\section{Abstract（草稿 v2，终局数字）}
长上下文推理中，KV 缓存访问同时制约 decode 与 prefill。现有

training-free 稀疏注意力方案面临精度-速度的困难权衡：基于下界近

似的方法（Quest）在长上下文检索任务上质量崩塌；基于训练的索引

（DSA）引入额外参数与训练成本。我们提出 TLI，一个两级 training-free

稀疏注意力索引：块级 minmax \textbf{上界}粗筛保证无漏选，far/near 分区

token 级精筛保护远端关键 token。在统一 harness 下，TLI 选择链相对

dense 打分实现 1.46$\times$@32K $\rightarrow$ 5.09$\times$@128K kernel 级加速；

e2e 收益区（64K 单请求）1.285$\times$ 领先 dense。质量上（Qwen3-8B，

LongBench 13 任务 + RULER 33 任务双基准）：TLI 终局配置

LongBench \textbf{50.54}——training-free 稀疏索引器首次超过 FullKV

（50.36，+0.18）；musique 多跳 far-heavy 任务 34.76 为全方法新高

（FullKV +2.62）。RULER 87.93 逼近 FullKV（88.71），且长度梯度

干净（4K $-$0.14 $\rightarrow$ 8K $-$0.25 $\rightarrow$ 16K \textbf{+0.91} 反超）。方法论贡献：

trace 重放 mass 排名与 e2e F1 排名系统性反转（五臂全反）——

双口径必须都测都报告；全部负结果（聚类代表/监督投影/TC 化/

静态层跳过）同机同口径诚实入册。

\section{1. Introduction}
\textbf{瓶颈}：长上下文 LLM 推理的注意力计算受 KV 缓存带宽制约——

131K 上下文 $\times$ 8B 模型的 KV 读取远超计算量，decode 每步全量访问

KV 成为吞吐上限；prefill 同样受全注意力带宽制约。

\textbf{现有方案的困境}：(i) training-free 方案中 Quest 的 page-min

\textbf{下界}分数近似会漏选真实高分页——干扰项随长度超线性增长时

质量崩塌（我们实测 RULER 16K multikey_3 仅 21 分 vs FullKV 100）；

(ii) 训练类索引（DSA/MoBA）引入可学习参数与 warm-up 成本，

且 indexer 质量依赖训练分布；(iii) HISA 等 block-coarse+token-refine

两级结构已被验证有效，但\textbf{表示（上界 vs 下界）与预算组织（分区

vs 全池）的质量-速度影响未被系统刻画}。

\textbf{我们的方案}：TLI 两级索引——L1 块级 minmax 上界粗筛（低频

position-stable 子空间 d'=32 + 4bit 量化，无漏选保证）；L2 far/near

分区 token 级精筛（far 独立配额防挤出，最优配比 $\alpha$=0.125 /

$\beta$=0.375 / $\gamma$=0.125）；D' 感知型 per-request gate（安全省算力

保守开关）。kernel 化贯穿（fused L1 / dual 级联 / 统一稀疏

attention fused kernel / DS topk）。

\textbf{贡献}（与实验编号一一对应）：

1. \textbf{training-free 降维自由度的系统刻画（子空间选择）}：

位置稳定低频子空间质量不打折（E3：0.729 vs 全维 0.732），

\textbf{两段互补机理}（E73/E73b）：tail32 = rope 低频尾 16 维（位置

感知段，单独 0.576）+ nope 尾 16 维（内容稳定段，单独 0.387），

拼接 0.811 $>$ 任一（+0.24 组合增益，全链同特征口径）；进一步降维以无监督

细筛 PCA d16 近无损（E65：0.766 vs 0.804），且跨 kv-head 共享
SVD 基 d16 同样近无损并优于 per-head 基（E76：8/8 样本追平
tail32，GQA head 冗余 $\Rightarrow$ MLA 式单投影缓存的 training-free
代理，投影矩阵跨 head 存一份）；\textbf{训练投影的

口径鸿沟}（E66 trace 成立 92-94\% vs E71-B e2e 崩坏——投影基

对 decode q 分布漂移脆弱，尾维位置先验分布无关恒稳）；非线性
流形学习双判否定（E76：UMAP 保邻域不保选择排序 $-$4pt，fit
成本 80-167s vs 增量索引 0.128ms/token 四个数量级不可行；t-SNE
BH 16 维 OOM/病态）——

training-free 路线的降维自由度来自位置先验而非学习/自适应。

上界保证与 Quest 下界近似的长上下文质量分化（RULER 终局

+7.98@16K vs Quest）；

2. \textbf{far/near 分区预算（B'）}：GQA far 集中特性下的防挤出设计，

e2e 双口径判决成立（LongBench +0.25 / RULER +0.17 vs 单池），

多跳 far-heavy 任务增益最纯粹（musique +3.02 vs 单池）；

聚类代表降级为消融——负结果；

3. \textbf{感知型 per-request gate（D' 演进）}：静态掩码跨任务不泛化

（$-$4.8~$-$5.9）$\rightarrow$ prefill 动态信号（last1 corr 0.924）$\rightarrow$ 真

触发区间（$\tau$=0.005）多跳微损不崩——gate 定位为「安全省算力

的保守开关」而非精度增益点；

4. \textbf{系统级 kernel 化与双口径评测方法论}：kernel microbench

与 e2e 的口径差（host-GPU 流水线效应）系统案例（#65）；

\textbf{口径鸿沟方法论贡献}：trace 重放 mass 排名与 e2e F1 排名

五臂系统性反转（E72），离线快筛判决不可替代 e2e；

负结果全程入册（TC 化/TMA/聚类/near-DS/静态 gate 五项 No-Go）。

\section{5. Related Work}
- \textbf{稀疏注意力索引}：Quest（page 采样 + 下界近似）、SnapKV/

PyramidKV（observation-based 压缩）、H2O（累积重要性）。TLI 的

差异 = 上界（vs 下界）+ 分区预算（vs 全池）+ 两级级联（vs 单级）。

- \textbf{训练类 indexer}：DSA（DeepSeek V3.2，I=Σw·ReLU(q·k)，64$\times$128

FP8 top-2048，warm-up 1000 步）、MoBA（gated block 稀疏）。

TLI training-free/weight-free，与其在 kernel 级统一 harness 对比。

两者构成方法论分界：DSA 用训练（KL 对齐 attention 分布）换选择

能力，可学任意投影；training-free 只能依赖与 q 分布无关的位置

先验——trace 离线成立 $\leftrightarrow$ e2e 崩坏的口径鸿沟（E66$\rightarrow$E71-B）

正是这条分界线的实证刻画，而非实现失误。

- \textbf{两级结构}：HISA（COLM 2026，block-coarse + token-refine）

与 TLI 同构——「two-level」本身非 novelty；TLI 的增量 = 表示

选择（上界）+ 预算组织（分区）+ 质量代价定位的系统刻画。

- \textbf{推理系统}：FlashAttention 系（计算侧）；PagedAttention/

vLLM（显存组织）。TLI 在 sglang 生产形态集成（paged 寻址 +

增量索引 + CUDA graph）。

\section{6. Limitations \& Future Work}
\textbf{精度侧}（诚实定位）：TLI 终局配置在 LongBench 13 任务上首次

超过 FullKV（50.54 vs 50.36），但增益幅度在噪声边缘（+0.18）；RULER

最优臂 87.93 仍低于 FullKV 88.71（$-$0.78）与 TIA 88.35（$-$0.42），

残余代价集中于 multikey\_3（16K：75-80 vs TIA 89）——4bit 预算粒度

在超多干扰 key 任务上主导。单跳检索口径放大该代价，多跳口径放大

far 分区保护收益，两表并报，用户可按任务形态选择。E72 冠军臂

RULER 87.59（补全已跑）：预算配比的任务形态依赖性如实报告。

\textbf{速度侧}：多请求批量形态（TP2 bs16 64K）仍差 dense 8%——

launch-bound（逐请求 Python 循环放大固定开销，GPU 名义满载但

带宽 util 仅 10-11%）；跨请求批量化 forward_extend 是明确修复

方向（decode 侧同类方案已验证 3.8$\times$），列为 future work。

\textbf{其他}：动态 gate 的 far_stat 为 per-layer 单值，混合 batch

跨请求污染（生产语义应 per-row）；H100 吞吐主表（TC 形态下

#65 优化链的预期收益不同）留机器可用后补。

\section{2.1 L1：块级 minmax 上界粗筛（子空间）}
\begin{figure}[h]\centering
\includegraphics[width=0.95\linewidth]{figures/fig2_dim_reduction_story.pdf}
\caption{降维自由度来自位置先验：(a) tail32 两段互补（E73b）；(b) 共享 SVD d16 八样本逐点追平 tail32（E76）；(c) 线性优于非线性、共享优于 per-head（E65/E76）}
\end{figure}

将 KV 缓存按块组织（block=64）。对每块每 kv-head 维护低频尾维子空间

（d'=32，Qwen3 rotate_half 的 position-stable 低频维，E3 实证：

lowfreq mass recall 0.729 $\approx$ 全维 0.732，random 0.32 / highfreq 0.137

崩溃）上的 min/max 上界，4bit 量化存储（uint8 + scale 三张量，128$\rightarrow$

40B/token-head，M6）。

\textbf{子空间的两段互补性机理（E73 机制分解）}：tail32 = rope 低频

尾 16 维 + nope 尾 16 维。单独做 far 全链各捕获 0.576 / 0.387，

\textbf{拼接 0.811 > 任一}（互补组合增益 +0.24）——32 维子空间的

威力不是「低频连续段」，而是\textbf{位置感知段（rope 低频，长程检索

主力）+ 内容稳定段（nope 尾）各取所长}。纯 nope 全链（64 维最佳

0.435）与单段对照均被否定（E73 negative result），这解释了 E3 时代

random32 崩溃与 tail32 稳健的差异根源。

Query 打分用块上界的\textbf{乐观侧}：与 min 的最大距离或与 max 的最小

距离构成该块对任意 token 的分数上界——\textbf{上界保证无漏选}（对比

Quest 的 page-min 下界近似：长上下文干扰项超线性增多时下界漏选

真实高分页，RULER 16K Quest multikey_3 21 分的根因）。取 top-K1

块进入 L2（K1=128）。

\textbf{压缩表示的量-界权衡}（E4c 严格 token 预算 + per-head 加权口径）：

4bit 量化分数并列（tie）是主要质量风险——L1 层面可容忍（多选由

L2 吸收），L2 层面不可（near 池 DS No-Go：jaccard 0.72）。

\section{2.2 L2：far/near 分区 token 级精筛（B'）}
L2 把 K2 预算划分为两个池：

- \textbf{near 池}（滑窗近端）：最近 sw_lo 个 token 的强制覆盖——

局部性强（H1：dense top-1024 mass 的 near 层占 0.16-0.29），

因果滑窗语义下天然精确，无需打分。

- \textbf{far 池}（远端候选）：L1 入选块的 token 级 4bit 精筛（TIA

同款 token 级量化打分，far 区 $\approx$ oracle，E4c L03 0.999）。

\textbf{B' 的价值 = 防挤出}：无分区时 far 候选与近端高分 token 在同一

池竞争，far-heavy 层（GQA head 级 far mass 极不均，L03 head3 独占

0.804）的远端关键 token 会被近端挤出。分区给 far 独立配额

（far_tokens 128-256 即饱和，E63 配比消融），近端配额扣减带

near_floor 保护防边界回退。

\textbf{B' 的 e2e 判决（终局）}：分区 vs 单池在双基准上成立——

LongBench +0.25（50.41 vs 50.16）/ RULER +0.17（87.93 vs 87.76，

16K +0.91）；多跳 far-heavy 任务增益最纯粹（musique +3.02）。

与 trace 重放 mass 口径（宽预算下 mono 单池微胜 $-$0.005）的

分歧坐实为预算口径问题：\textbf{分区收益的本质是紧预算下的预算

分配，而非候选质量}。

\textbf{聚类代表的教训（negative result）}：开题的创新点 B（kmeans 远端

聚类代表）在严格 token 预算下无一致优势（块 scatter-amax 0.09-0.39

最差）且聚类中心非上界有漏选理论空洞——B 的 lazy 维护假设仍成立

（E7 增量 assign recall 衰减 $\leq$0.03）但表示本身降级为消融项，

B 重定位为分区预算设计（B'）。

\section{2.3 D'：离线层跳过 + 动态 gate}
离线校准：trace 分析显示 far 质量呈层间轮廓（部分层 far mass 近零

——这些层的注意力几乎全部由 sink+near 覆盖）。离线平均轮廓可跳

13/36 层（precision 0.92-1.00），但\textbf{全局静态掩码跨任务不泛化}

（musique/qasper/multifieldqa 掉 4.8-5.9，E5b；per-task 重校准也

失败——长度失配 + GQA head 级 far 被平均口径低估）。

升级为 \textbf{prefill 动态测层 gate}（#60）：末 chunk 一次 softmax

far 统计 $\rightarrow$ far_stat 双峰（musique 18 层 <0.01 vs 其余 0.017-0.26）

$\rightarrow$ 阈值切自然间隙 $\rightarrow$ decode select 幂等置位 skip_far。

\textbf{升 $\tau$ 真判决（E67 双臂梯度，触发率实质非零——$\tau$=0.005 下

11.8\% 实体级输出分歧 vs 默认 $\tau$=0.01 的 1.1\% 近 no-op）}：

far-heavy 多跳双任务 vs gate-off（27.57/40.37）：$\tau$=0.005 $\rightarrow$

musique 27.80（+0.23）/ qasper 39.96（$-$0.41）；$\tau$=0.015 $\rightarrow$

musique 27.84（+0.27）/ qasper 39.70（$-$0.67）。梯度单调（$\tau\times$3

$\rightarrow$ 损失 $\times$2.2），真触发区间下\textbf{微损不崩}（对照静态版

掉 4.8$\sim$5.9）。

\textbf{gate 终定位 = 安全省算力的保守开关而非精度增益点}：

per-request 动态信号（prefill last1 $\leftrightarrow$ decode corr 0.924）防住了

反向错误（far 重要的层不跳），但正收益未兑现。

已知限制：stat 为 per-layer 单值，混合 batch 跨请求污染（生产

语义应存 per-row，TODO）。

\section{2.4 系统集成（sglang 生产形态）}
- \textbf{paged 寻址}：选择输出逻辑位置 $\rightarrow$ req_to_token 间接 $\rightarrow$ KV pool

槽位，与生产 KV 布局零拷贝对接。

- \textbf{O(n) 精确增量索引}：每 token 增量更新块界（增量==全量重建

逐位一致，0.128ms 与 S 无关；预分配几何扩容）。

- \textbf{共享 index pool}：per-layer 预分配 [R, cap]（kq/kmin/kmax），

decode 批量 select 全 eager ~15 launch 与 bs 无关。

- \textbf{CUDA graph}：capture 区域零 host 同步 + 统一增量图内路径，

replay 逐位一致。

- \textbf{早期行修复}（#58）：首 chunk t<K2 行均匀重复 grid——非因果

泄漏的根因修复（30B 生成崩坏的教训，8B 同 bug 耐受未崩，如实

报告）。

\section{3.0 设计约束（H20 形态）}
\begin{figure}[h]\centering
\includegraphics[width=0.85\linewidth]{figures/fig10_m8_kernels.pdf}
\caption{M8 kernel 微基准}
\end{figure}

H20 的 Tensor Core 吞吐仅为 H100 的 ~15%，而 HBM 带宽同级

（4TB/s）——\textbf{选择/打分类 kernel 的第一性约束是带宽而非算力}。

ρ 实验数据（带宽利用率 vs 计算强度）显示打分 GEMV 在 d'=32 形态

下 deep memory-bound，TC 化收益无法兑现（§8b-18 No-Go 如实

\section{3.1 Fused L1 块打分（E8-2）}
朴素实现：逐块 gather K 子空间 $\rightarrow$ 反量化 $\rightarrow$ einsum $\rightarrow$ 写回，每块

5-6 个小 kernel。Fused 版：单 Triton kernel 内完成 gather + 4bit

反量化（共享 scale 表）+ GEMV 打分 + 块级规约，输出直接为块分数。

\textbf{3.6$\times$（32K 形态）/ 1.6$\times$（131K）}，块 id 对拍与 eager 逐位一致。

\section{3.2 L2 级联 Dual Kernel（M8-KernelC）}
L2 需同时对 far/near 双池打分取 topk。Dual kernel 单 launch 完成

分区 topk：候选块展开为 token 粒度打分，\textbf{池边界即因果边界}

（far 池上界 $\leq$ t+1-near_len、near 池 < SW_LO——替代 eager 的

fine 矩阵因果 mask，L1 垃圾块天然落池外）。

关键工程发现（负结果资产）：

- \textbf{纯 kernel 版 No-Go}：4bit 分数并列过选（130-256/head 无人

兜底）+ 120 轮二分串行反慢 4.5$\times$——\textbf{L1 能容忍多选（L2 吸收）、

L2 不能}，混合形态（Triton pass1 打分 + torch.topk + 精确

复制）为终态。

- \textbf{bf16+pad 直出}（#65）：OUT_BF16 constexpr 分支使 far/near

分数直接以 bf16 输出到 pad 对齐宽度（pad 列 -inf），消灭 fp32

[n,Hkv,Tc]$\times$2 物化 + cast/pad 复制链（profiling 中 elementwise

16.3% $\rightarrow$ 0）。

- \textbf{CHUNK 形态调优}：64/num_warps=4 最优（12.1 vs 14.9/17.7ms，

与 M8-2b compact 路径结论一致）。

- \textbf{TMA 转置写布局 No-Go}（§8b-20）：写侧假设证伪，实测反慢。

\section{3.3 M11：统一稀疏 Attention Fused Kernel}
选择完成后，稀疏 attention 本体（gather 候选 K/V + softmax +

PV）的 eager 路径需 [n, K2, D] fp32 双物化。M11 单 Triton kernel

完成 gather + online softmax + 输出直写 bf16，\textbf{kernel 级

11-16$\times$}。工程陷阱记录：q_raw 为父张量切片 view 时行 stride ≠

H*D（实测 6144 ≠ 4096），kernel 寻址假设行连续 $\rightarrow$ 必须

contiguous 化（一次 bf16 拷贝仍远快于 eager fp32 双物化），

否则 row$\geq$1 全部读错位置（e2e 乱文根因）。

\section{3.4 DS Topk（DeepSelect 分数路径）}
4bit 打分输出可用数值判别结构（DeepSelect 类）替代 torch.topk：

L1 与 far 池接入（\textbf{decode 侧净效果 bs16 +10%}），near 池保留

torch——\textbf{No-Go 教训}：near 池压缩表 ~2048 有限项挤在 4bit 格点

极少数分数值（tie 组巨大）$\rightarrow$ 集合 jaccard 0.72。tie 打破差异与

候选分数离散度强相关，\textbf{接 DS 前必须按池预判}。

CUDA graph 约束：DS host 端 pad/end 分配不可进 capture 区域，

graph 捕获时自动回退 torch.topk（`is_current_stream_capturing`

门控）。

\section{3.5 Select 调度链的消除（#65）}
两个隐藏瓶颈的发现与修复（microbench 测不出、e2e 才显形的

口径盲区案例）：

- \textbf{早期行 Python 循环}（#58 修复引入）：首 chunk ~1024 行 $\times$

arange/cat/index_put $\approx$ 5K launch + 3K 次 .item() 同步 $\rightarrow$

chunk0 65ms。向量化 `where(j<cut, j//reps, j-cut)` 单 op 构造

uniform grid，4$\times$。

- \textbf{3 处 host 同步}：fast_path 判定 `.all().item()` / empty 段

`.any()` / early 段 `.any()` $\times$ 生产形态 $\approx$ 10 万次队列排空。

修复 = kernel 路径可用时直接跳过判定 + `t_min_hint` host

参数（forward_extend 的 prefix 是 Python int，可判「无 empty

行 / 无 early 行」跳过同步）。8B e2e prefill $-$6.7%。
