# Two-Level Attention 独立库发布与维护建议

日期：2026-10-08  
状态：设计建议，尚未实施迁移，也未完成新的 GPU 性能复测。  
依据：本次已核对的 `Chosen-David/sglang`、`two-level-indexer` 分支快照 [`c7b1087`](https://github.com/Chosen-David/sglang/tree/c7b1087e76c91bbe89881548912943cde5cb7075)，以及其中的 `TASK.md` 和英文稿贡献、方法、实验边界部分。此 SHA 是分析依据，不代表后续远端不会更新。

## 1. 建议结论与给维护者的话

**建议将 Two-Level Attention 单独发布并维护为一个可安装、可复现实验的核心库，把 SGLang 接入作为可选 adapter。** 论文的核心方法不必绑定 SGLang，也不必依赖多卡实验；但独立库仍需提供真实模型质量测试和整模型推理测试，不能只发布一个 attention 文件和局部 kernel 耗时。

可以直接向维护者提出：

> 建议将当前 two-level attention 从 SGLang fork 中抽取为独立核心库，统一维护子空间选择、near/far 两级筛选、索引更新及高性能 attention kernel；提供轻量模型接入和质量、kernel、整模型生成三类可复现实验入口。SGLang 保留为可选适配层，引用同一份核心实现。论文以方法与完整推理链的质量—成本权衡为主，框架兼容性和已有部署实验作为补充证据。迁移前后核验语义一致性，保留现有负结果和原始日志，不通过更换实现或实验环境掩盖性能边界。

独立库的价值在于降低复现与维护成本：读者无需理解整个 serving 框架即可测试核心方法；算法修复只维护一处；框架版本变化也不会直接改变核心实验入口。它并不自动带来性能提升，也不构成独立的科学创新。

## 2. 核心范围与贡献边界

必须保留用户定义的流程：**先子空间选择，再划分 near/far，两端均执行 L1 粗筛与 L2 细筛**。保持前 4 层 Full Attention 的当前实验策略，明确 sink、sliding window 和预算扣除规则。流程和配置应能从日志复查，不能只写在 README 中。

| 内容 | 独立库中的位置 | 论文中的作用 |
| --- | --- | --- |
| 子空间选择及完整 RoPE 旋转对处理 | 核心选择逻辑 | 候选机制，需要与相关方法公平比较 |
| near/far 划分与 α、β、γ 预算分配 | 核心选择逻辑 | 优先论证的候选贡献 |
| L1、L2、稀疏 attention、增量索引 | 核心算子与 kernel | 支撑完整链路效率 |
| 五种基础组合、两种聚类原语 | 配置与参数化实验 | 消融和设计空间，不逐项包装成创新 |
| 请求级 gate、远端跳过 | 可选策略 | 有质量与净收益证据后再作为贡献 |
| SGLang 分页、批处理、CUDA Graph 接入 | 可选 adapter | 部署兼容性与补充实验 |
| TP/PP、多卡调度 | 当前不作为核心依赖 | 模型装载需求或系统扩展，不默认作为创新 |

五种组合应完整保留，名称顺序为 `(far, near)`：

| 配置 | far 代表形式 | near 代表形式 |
| --- | --- | --- |
| `cavg` | cluster | avg |
| `mavg` | minmax | avg |
| `aavg` | avg | avg |
| `ccluster` | cluster | cluster |
| `mminmax` | minmax | minmax |

聚类原语保留 k-means 和基于余弦相似度的贪心聚类。共享接口和实验脚本，避免为每种参数组合复制实现。未完成同条件扫描前，不宣布某个组合是全面最优。

还应纠正当前创新定位中的两个问题：

1. **Quest 已使用 min/max 上界。** 不能将“上界替代 Quest 下界”当作差异；应比较预算分配、筛选粒度、子空间和实现成本。[Quest 原文 §3.4](https://arxiv.org/html/2406.10774v1#S3.SS4) 明确给出了该上界。
2. **按上界取固定数量的 top-K 块不保证不漏选。** 对 `q=(1,1)`，块 A 含两个 `(5,5)`，真实最高分和上界均为 10；块 B 含 `(100,-100)` 与 `(-100,100)`，真实最高分为 0、上界为 200。只保留上界最大的一个块会漏掉 A。上界有效性、选择召回与最终生成质量必须分别验证，量化元数据也需单独核验。

[FASA v3](https://arxiv.org/html/2602.03152v3) 已研究频率分块、经校准选择的子空间和完整频率对。因此，“降维”和“完整旋转对”本身不能直接视为新贡献。固定低频选择是否减少校准成本、是否适合索引复用，以及与 near/far 的组合收益，才是需要实验判断的具体差异。

## 3. 建议的库组织与接口

以下是建议结构，不是已经存在或可以立即调用的接口。

| 路径 | 职责 |
| --- | --- |
| `src/twolevel_attention/config.py` | 配置定义、预算与非法组合校验 |
| `src/twolevel_attention/reference.py` | 易读参考实现，作为正确性 oracle |
| `src/twolevel_attention/index.py` | 索引构建、更新、缓存有效性与重置 |
| `src/twolevel_attention/selection.py` | 子空间、near/far、L1/L2 与策略组合 |
| `src/twolevel_attention/kernels/` | 优化算子、后端能力检测与数值边界 |
| `src/twolevel_attention/adapters/` | 轻量模型接口及可选 SGLang 接入 |
| `tests/` | 参考对照、边界、状态恢复和 adapter 一致性 |
| `benchmarks/` | 参数化 kernel、完整算子链和生成性能测试 |
| `evals/` | 任务输入、生成、质量评分与结果核验 |
| `examples/` | 最小 attention 示例和真实模型生成示例 |
| `docs/` | 方法、支持矩阵、复现指南、限制和变更记录 |

尽量搬迁并复用现有有效实现和脚本，不因拆库重新造一套评测体系。核心依赖按实际实现确定；serving 框架、数据集评测工具作为可选依赖，不自动安装全部 runtime。

接口至少明确以下契约：

- Q/K/V 的 shape、layout、dtype、设备、stride 和 GQA 头映射；子空间维度仅用于哪些打分阶段，最终 attention 使用哪些维度。
- 索引状态与模型、层、请求、KV 版本、配置绑定；不允许跨请求或输入版本复用失效状态。
- 选择输出采用逻辑 token 位置；物理 KV 地址转换由 adapter 处理；无效位置、排序、去重和有效计数有统一约定。
- near/far、sink、SWA 的边界、重叠消除、因果可见性和总预算规则，处理预算为零、短序列和不足预算的情况。
- 优化路径、参考路径、fallback 及不支持条件可观察。质量参考路径不能被标成稀疏加速路径。

SGLang adapter 不再维护另一份算法副本。它负责框架元数据、分页映射、调用生命周期与资源管理；核心库负责算法语义。adapter 与框架版本固定并记录，不能把一个版本通过的结果推广为所有版本兼容。

## 4. 实验保留与论文安排

**独立模型 E2E 和 serving E2E 是两种不同验收。** 前者测模型从输入到实际生成的质量与耗时；后者还包括批处理、调度、分页管理和请求负载。没有做后者时，应缩小声明，而不是用 kernel 加速倍数替代。

| 实验 | 必要性与安排 |
| --- | --- |
| LongBench、RULER 等真实生成质量 | 正文核心；固定模型、输入、模板、解码和总 token 预算，报告任务差异与失败 |
| 五种组合与两种聚类原语 | 完成同条件比较；关键机制放正文，完整扫描放附录 |
| 子空间、near/far、α/β/γ、gate 消融 | 在开发集选择设置，保留未见测试；不能仅凭 attention mass 判断最终质量 |
| 单 kernel 耗时 | 正文性能分解；报告正确性、warmup、重复、噪声与测量方法 |
| 完整 attention 算子链 | 正文核心；包括筛选、top-K、gather、attention 和索引维护开销 |
| 整模型生成耗时及显存 | 正文核心；分别报告 prefill、decode、总请求耗时及索引附加内存 |
| SGLang adapter 一致性与代表性部署测试 | 补充材料或附录；若仍主张生产部署能力，则需相应充分验收 |
| 更多 TP/PP 与多卡配置 | 暂缓扩展；仅在模型装载或论文系统主张需要时继续 |

主结果可以使用装得下模型和目标上下文的单卡。多张已有且获授权的 GPU 可以并行跑独立质量任务，但性能对照应避免共卡和共享瓶颈干扰；不能将多卡实验排队提速写成方法推理加速。

计时必须覆盖本方法新增的成本：prefill 索引构建、每步更新、gate、筛选、最终 attention，以及实际 adapter 转换。报告长短输出条件，避免仅用长 decode 摊薄构建成本。质量与性能即使采用不同执行路径，也必须说明并证明方法语义对应，不能合成一个实际上未测过的性能—质量点。

已有 SGLang 数据按证据状态处理：

- 公平、有效的负结果保留；若整请求更慢，正文也要明确总体性能边界，不能只把不利结果藏在附录。
- 受 bug、不同 prefill 语义或协议混杂影响的结果保留日志，标为失效、不可比或待重验，不进入正式比较。
- 迁移后的结果与旧结果分开绑定实现及输入版本；更换框架、模型或硬件时，不直接拼接为同一曲线。

## 5. 迁移与发布验收

建议分阶段执行，不先删除现有代码或结果：

1. **冻结来源。** 保存源 commit、核心文件清单、依赖、输入与输出 hash、已有问题和有效基线。论文原始观测保持可追溯。
2. **抽取核心。** 将参考实现、优化实现、五种组合和两种聚类原语迁入独立包；保持方法语义，不夹带新的算法改动。
3. **核验迁移。** 用相同输入比较迁移前后的候选位置、attention 输出、增量更新与全量重建。精确离散结果按既定 tie 规则验收；浮点输出提前设容差，不要求不同 kernel 一律逐 bit 相同。
4. **完成轻量模型接入。** 验证前 4 层 Full Attention、后续稀疏层、cache 更新和真实生成；不能停留在随机 Q/K/V。
5. **对照真实实验。** 固定输入、模型、预算及协议完成质量、完整算子链、整模型性能；保留失败与修复复跑。迁移验收通过不等于算法效果更好。
6. **连接可选 adapter。** SGLang 调用已冻结的核心版本，核验分页映射、批内变长、请求复用、取消/重置及适用的 CUDA Graph 路径。
7. **发布可复现版本。** 固定 release commit/tag、依赖与硬件支持范围，给出可执行命令、输入来源、原始记录和评分规则。发布新仓库、包或迁移删除需按用户授权执行。

发布前至少满足：

- [ ] 干净环境可安装，最小示例真实运行。
- [ ] 五种组合与两种聚类原语的支持情况准确，未支持项明确报错。
- [ ] 短序列、边界块、变长、GQA、因果遮罩、重叠保护区和预算边界通过。
- [ ] 索引更新、状态重置及请求隔离通过；静态/动态策略语义有可追溯测试。
- [ ] 优化 kernel 与参考实现正确性通过，真实模型质量与生成链路已执行。
- [ ] 性能记录包含实现、输入、模型、依赖和硬件版本；计时不漏新增成本。
- [ ] 文档的已验证范围、fallback、负结果与实验事实一致。
- [ ] 代码与依赖许可核对完成；不将不获授权的论文全文、模型权重或私有数据打包发布。

## 6. 论文叙事与维护建议

若决定采用独立库路线，应一致调整摘要、贡献、方法、实验和限制部分：以训练免修改的稀疏索引方法及其可复现实现在主线组织证据；将 SGLang 接入表述为可选部署适配。不能保留“生产级 serving 提升”的强声明而取消其验收。

现阶段建议重点验证三条候选贡献：

1. **区域预算机制：** near/far 分别粗筛、细筛，在相同总预算下改善质量—成本权衡。
2. **索引适配的子空间：** 固定完整低频旋转对是否在无需校准、索引维护成本和真实生成质量之间有可验证优势。
3. **完整链路实现：** 从索引构建到生成的真实效率及适用边界，而非仅报告局部 kernel 的最佳倍数。

这些是需要证据支持的研究主张，不是本建议稿已经证明的结论。动态 gate 和轻量配置选择继续按 TASK 做有界验证；若净收益不足，作为负结果或设计经验保留。

维护上采用单一核心实现、参数化实验入口、明确支持矩阵和版本化结果。论文对应 release 冻结，后续开发结果单独保存。先支持已经真实验收的模型与硬件，按实际需求扩大覆盖，不追求与所有 serving 框架同时集成。
