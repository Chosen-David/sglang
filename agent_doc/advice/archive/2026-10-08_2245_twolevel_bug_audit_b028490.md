## 3. `TL-AUD-MERGE-001`：缺失 RULER 任务时 QA 被错分到 RULER 组

### 3.1 违反的契约

文件头和第 68 行把结果定义为“RULER 四任务 + QA 两任务”，并称 QA 未全时自动跳过。但当前实现先把所有完整任务按字典插入顺序放入同一个 `rows`，随后用位置切片分组：

```python
groups = {
    "RULER 四任务": rows[:4],
    "QA 两任务": rows[4:6],
}
```

这隐含要求前四行永远都是四个完整 RULER 任务。一旦某个 RULER task 缺一侧方法，该 task 不会进入 `rows`，紧随其后的 QA 行就会前移。脚本没有失败，也没有在分组标题中暴露串组。

### 3.2 最小可运行复现

实际执行的是源码基线中的原脚本副本，只把两个硬编码绝对路径替换为临时 fixture 路径；算法代码未修改。fixture 含 3 个完整 RULER 任务和 2 个完整 QA 任务，两 seed 均齐全。

- 原脚本 SHA256：`dfa0cf60116e68379f71eef6794af9359609bf2b386c0e074f9959c0168735df`
- RULER fixture SHA256：`086b63e3992b3d49f764ecd545f54ab09ac4ae720de40ede20c221e65a4394ff`
- QA fixture SHA256：`77b43d3ce0dd9b3cc6aec5ecb6b2220c0aaae9364aaeb87997d2930b5cd2bb15`

构造分数：三个 RULER gap 均为 `+1`，`qa1` gap 为 `+10`，`qa2` gap 为 `+20`。实际输出：

```text
RULER 四任务均值 pooled: FullKV 26.500 / TLI 29.750 / gap +3.250
QA 两任务均值 pooled: FullKV 200.000 / TLI 220.000 / gap +20.000
```

预期应为：

```text
RULER（当前 3 个完整任务）gap = +1.000
QA（当前 2 个完整任务）gap = +15.000
```

实际 `+3.250 = (1+1+1+10)/4`，直接证明 `qa1` 被纳入 RULER；QA 组又只剩 `qa2`。

### 3.3 对已有数据的影响

本轮读取并执行了仓库当前两份真实结果：

- `research/results/tli_ruler_results.json`，SHA256 `f5f344a5f6d562f6d41d453ad77955404ced1988aba83f7491a2beff59df86b0`；四个 RULER task 在 FullKV/TLI、两个 seed 下均齐全。
- `research/results/tli_ruler_qa_results.json`，SHA256 `2dab5cff15c5720560c93942f910929baadc6bdbf5224fd94a718636e54d022e`；`qa1/qa2` 在两方法、两个 seed 下均齐全。

当前实际输出为 RULER gap `-0.231`、QA gap `-0.175`；由于恰好满足 4+2 顺序，本缺陷不改变这组结果。受影响范围是后续断点续跑、某任务失败、只刷新部分 tag，或字典顺序变化后的汇总。此时错误很可能被当成有效论文数字，因为脚本仍正常退出。

### 3.4 建议修复与最小回归

不要按 `rows` 的位置推断域。装载 source 时同时保留 `domain in {ruler, qa}`，或使用显式 task allowlist，将行直接追加到 `group_rows[domain]`。输出每组均值前同时打印 `included_tasks`、期望数量与完整性状态；论文终表模式应在缺必需任务时非零退出，探索模式才允许 partial，并在标题中写出 `3/4`、`1/2`。

最小回归矩阵：

1. 完整 4+2：结果与当前输出逐位一致；
2. 缺一个 RULER：QA 不得进入 RULER，终表模式失败；
3. 缺一个 QA：RULER 不变，探索模式明确显示 QA `1/2`；
4. 打乱 JSON task 顺序：两组成员和均值不变；
5. 某 task 仅 FullKV 或仅 TLI：不得静默进入任一均值。

## 4. `TL-AUD-Q4-FP16-001`：FP16 常量行的量化 scale 可为 0

### 4.1 调用链与触发机制

`TIAIndexer.min_max_per_token_quant` 与 `TwilightIndexer.min_max_per_token_quant` 都先在输入 dtype 内计算：

```python
scales = (max_val - min_val).clamp(min=1e-9) / 15
return clamp(round((x + zeros) / scales), 0, 15) * scales - zeros
```

TLI 继承 TIA 的实现，并在普通 L2 路径 `tli_indexer.py:296` 调用；投影路径 `tli_indexer.py:247-253` 先 `.float()`，因而该投影臂不满足 FP16 前提。

NumPy 以 FP16 忠实复现相同算术，输入为一个 32 维全 1 常量 token：

- 输入字节 SHA256：`cf291829a08fd433380a44efecde63fd60567375039ae9f57691587afbdef276`
- `float16(1e-9) == 0.0`
- `scale == 0.0`
- 输出 `finite=False`，32/32 个元素为 NaN。

这证明 epsilon 在 FP16 中不可表示以及常量行必然遇到零 scale；但本机没有 PyTorch/CUDA，尚未直接执行仓库函数，所以状态保留为 `suspected`，不能把 NumPy 复现写成 GPU 实测。

### 4.2 对已有数据的影响

本轮搜索到的 TLI e2e、RULER、kernel/attention 测试均显式使用 `dtype="bfloat16"`；BF16 可表示 `1e-9`。TLI 投影臂又把 `kp` 计算为 FP32。因此当前审查范围内没有证据证明已有 BF16 实验受影响。

风险位于：未来把 TIA/TWI/TLI backend 用于 FP16 模型，或单独开源 indexer 后用户自然传入 FP16 KV。随机连续 KV 恰好全维相同的概率低，但零初始化、裁剪/稀疏化、测试 fixture 或特殊投影可以构造常量 token；出现后 NaN 会进入 `k_qat` 与 L2 score，选择结果不再可信。

### 4.3 建议修复与最小回归

优先在 FP32 内计算 min/max、scale、quant/dequant，最后转回输入 dtype；对 `span == 0` 显式返回原常量，而不是依赖一个可能随 dtype 下溢的十进制 epsilon。修复后需验证非退化：

1. FP16/BF16/FP32 的常量 0、常量正值、常量负值均全 finite 且重构为原值；
2. 最小非零 span、普通随机输入、大幅值输入；
3. 修复前后 BF16 非常量输入的误差界与 top-k 一致性；
4. 直接调用 TIA、TWI、TLI 普通路径；TLI 投影路径作为不受影响对照；
5. 若 backend 宣称支持 FP16，补一次真实 Engine decode 与 L2 score finite 断言。
