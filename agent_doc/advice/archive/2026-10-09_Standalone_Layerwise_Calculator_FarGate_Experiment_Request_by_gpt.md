## 4. 三参数“计算器”：预算编译器 + 有限代理搜索

### 4.1 一个候选必须先能执行

对每条实际 query，用未 padding 的因果可见集合 U_q；保护集合 P_q=prefix∪SWA，按集合去重。中间集合 M_q=U_q\P_q。每层同 KV 头的 L1/L2 使用同一表示/同一可选投影；共享基不等于所有层共用一张基。最终 attention 仍读取原始全维 K/V。

将参数编译为 `(near边界, far边界, Bn,Bf,Tn,Tf,valid_masks)`：

- α决定 M_q 尾部的 near 范围。页对齐、末页与保护区交叠必须由统一边界函数给出；near 上界是 SWA 起点，而不是序列末端。当前旧代码的 padded 长度公式不能充当修正契约。
- 双池中 Bn=max(1,round(K1·β))，Bf=K1−Bn；明确 Python ties-to-even 或其他实际舍入规则，这里记录当前双池映射，修正后参考、优化和各支持路径必须消费同一 profile/预算编译器。单池是独立枚举模式，不能机械沿用双池解释。
- Kmid=max(0,min(K2,|U_q|)−|P_q|)。若 |P_q|>K2，明确保护优先导致预算例外或拒绝该 profile，不能仍报告“严格≤K2”。
- 标称 Tn=min(floor(Bn·b·γ),Kmid)，Tf=Kmid−Tn。实际合法性须按**选择后的有效唯一候选数量**检查，不用 Bn·b 代替有 padding/掩码的池容量。
- 返回逐头实际有效计数；禁止用跨头最大计数保证所有头合法，禁止 topk 以零 softmax 或 −inf 无效项填满。不足池采用预先写明的确定性截断/回退规则，不能悄悄跨池回补。

计算器输出必须保存两份：人类可读 α/β/γ，以及每个实际 S_q 的有效整数描述。先对所有校准/确认前缀检查再评估误差；生产新长度也使用同一边界检查，不因只在最终长度合法而直接复用。相同有效过程可去重，但须在所有消费前缀、方法、dtype、tie 规则上等价，不能仅凭单个长度的 Tn 相同合并。

### 4.2 优化目标及 head 耦合

令 dense 和稀疏的所有 query-head 输出分别为 y_h、ŷ_h，使用真实模型布局：

`Δo_l(q,c) = W_O,l · concat_h(ŷ_h−y_h)`；`E_l(c)=task/doc平衡平均[||Δo_l||²/(a_l²+ε)]`。

矩阵转置以框架实际存储为准；a_l是仅用校准 dense 输出算出的固定层尺度；a_l与ε必须在查看确认集前冻结，ε>0且具有输出平方的量纲/尺度，不随候选重估分母。零尺度层单列处理，非有限目标标为failed而非自动胜出。另报绝对误差、文档尾部误差和每任务结果。两 head 误差可经 W_O 抵消或放大，不能独立每头最小化再声称等价全层目标。先做两 head 反例与小序列模型 oracle；当前缺 W_O 的历史 P0′只能标未投影代理快照。

**首版选每层一组三参数、所有 KV 头共享参数，仍保留逐 KV 头实际掩码与诊断。** 若之后做 head-specific 表，使用真实 W_O 目标的组坐标更新，每次只改一个 KV 组、其余固定，再联合确认；不是各头互不相关的最优解。该扩展增加搜索与调度成本，不默认开启。

### 4.3 最小搜索与通过条件

先关闭 gate，固定一种方法、K1/K2、表示、层启用、dtype 和阶段路径。复用已有小 trace 做 oracle 修复，然后：

1. 在开发数据上为**相同 method**重新确定可比的统一参考 G*；mavg(.25,.125,.625) 是应纳入的候选，不是无需复核的 gold。不能将 avg/avg 的潜力判决外推给 minmax/avg。
2. 先用已有设计的 8 个代表稀疏层完成有效域、目标、median/tie 修复；只在合法的不同整数候选上回放。粗到细搜索和有限枚举参考用同一 trace、目标和资源记账。旧 336 网格可作参考，不要求每个候选跑一次整模型。
3. 校准文档与确认文档分离，不能同一文档切 query 后称独立确认；记录题材、长度与阶段分布。搜索次数、tie 容差和保留规则在查看确认结果前冻结。若多次查确认集调表，它转为开发集，必须另设最终测试。
4. 报告每层 G*、枚举、轻量选择的绝对/归一化误差和校准 regret、确认误差、计时及峰值内存；对接近零的改善分母不报夸大 recovery。8层小试只检验可行性，不能宣称全模型最优。
5. 只有独立确认具有稳定改善且计算器成本可接受，才扩为全稀疏层表并做一次联合真实生成。固定统一表与逐层表获得相同追加开发预算。层内误差改善不推出生成质量或速度改善。

主对照最初只保留 FullKV、修正后的统一配置、逐层配置，其他因素不动。若未见稳定优势，停止全模型大网格，交付负结果和更简单的统一配置；“近似同分选简单配置”是合法结果。

## 5. D′ gate：明确动作，再判断信号

### 5.1 动作契约（所有 gate 共用）

设 g_{l,h}(request,step)∈{0,1}，**1=far-on，0=far-off**。第一版优先层级 gate，减少分支碎片；head 级 gate 为可选扩展。

- g=0：far 不进入候选，near 的边界、Bn/Tn、打分与 tie 规则和 g=1 完全一致，prefix/SWA 始终保留；省下 far 预算不自动转给 near。near补预算是另一条消融，不混入本主实验。
- **近端分数的归一化范围也必须固定。** 本次核对的 HF reference 普通 4bit/GQA 路径先按各 query head 的全候选分数 softmax，再在 GQA 组内平均；去掉 far 会改变各头分母，可能改变组平均后的 near 排名，故只固定 Bn/Tn 不足以保证 near IDs 不变。诊断时可先由同一 far-on scorer 确定 near IDs 并让两臂复用（这可能已付出 far 打分成本，不能宣称省去该成本）。部署版可另行定义 far-independent 的 near scorer，先选 near 再决定 far；但这是需要重新校准与对照的新 policy，far-on/off 两臂必须同时使用它，不能直接冒充当前实现的等价优化。记录 softmax 范围、GQA 聚合顺序及 tie 规则。
- g=1：执行相同配置的正常 two-level。gate不确定、未校准长度或gate特征/预测无效时，只有原始QKV与索引仍有效才回退far-on。模型/表示版本变化须先刷新并验收匹配索引；原始张量非有限、索引无效或不支持空池时，拒绝计算、重建后核验，或走确实有效且已登记的fallback，不能带坏状态继续far-on。这里的正常 far-on fallback **不是 dense attention**，除非实际执行了另外登记的 dense 路径。
- 跳过 far 检索不删除原始 far KV。为了重新开启 far，索引需持续增量维护或按明确策略在启用前重建；标记版本与新进入 far 的 token，计入维护/重建成本。不能重新开启一个过时索引。
- 不能在全 far 精筛已经完成后才决定跳它。先划分可省的算子，再安排决策时序：gate→far L1/L2/gather/attention 是否调用。若决策依赖 far L1，就只能主张省 far L2/最终读取，不能把 far L1 也记为省下。

静态正确性测试必须逐层逐头检查 near IDs、保护 IDs、far有效计数、预算和输出：同一输入只改变 gate；g=0 时 far计数=0且 near IDs 不变。覆盖首尾部分页、短前缀、SWA交界、空far、GQA、不支持组合和状态切换。当前 `skip_far` 的分支行为先改为满足该契约或清楚注明不支持，不能以既有开关名代替验收。

### 5.2 四种信号，按成本顺序推进

| 方案 | 实际可用信息与决策时刻 | 用途/限制 |
|---|---|---|
| S：离线静态层名单 | 仅开发集校准得到，运行时直接查表 | 必要低成本对照；不声称每条请求都安全 |
| R：请求自适应名单 | 当前请求 prefill 中预先选定的因果 query；对少量 query 做 far-on/off 影子回放，得到局部输出扰动 | 本项目优先动态候选；只用当前输入、不读未来生成或答案。影子回放新增成本计入 TTFT；稀疏 prefill 不能凭空免费取得 dense oracle |
| Q：在线便宜风险分数 | 决策前可得 q 的范数/与校准分布的漂移、当前长度、已维护的 near/far 摘要；可选已计算的 L1 分数间隔 | 只能在开发集拟合/定阈值，不把低维分数当真实 far mass。先用 R/S 做基线；确认预测力后才上线 |
| O：全 far 真值 gate | 固定 trace 完整 far-on/off 输出和最终标签 | 仅离线诊断上限，不是可部署免费信号，也不能用确认/测试答案决定开启哪些层 |

R 的首版可将选中 prompt query 的输出误差尾部作为风险，结合离线静态校准的阈值输出请求层名单；prefill 为当前请求额外采样的 query 位置必须预注册且因果。开关只在名单冻结后的 decode 使用，以隔离“prefill测信号→decode用策略”。另外的 indexed-prefill方案需要独立因果实现与相应质量矩阵。

Q 首先用少量简单特征和阈值/小线性分数，不先训练大网络。标签可定义为该 trace 下 far-off 相对 far-on 的 `||Δo||²` 是否超过预先声明局部阈值；W_O 仍耦合 heads，因此以层级标签起步。far-on本身相对dense有误差：必须同时保存 dense、far-on、far-off 三者，不能把“接近far-on”写成“接近FullKV”。

允许短期迟滞和定期间歇 far-on 检查以减少抖动，但间隔、恢复规则和成本需冻结并测试。watchdog 只能发现已检查步骤的异常，不能保证在下次检查前不丢关键远程信息。近端 q 漂移小也不保证 far 不重要，必须有反例/压力集（主题突变、后续追问早段实体、长生成、far关键针）。

### 5.3 阈值、失败与净收益

不要默认沿用旧注释的 precision 0.92–1.00 或 far质量损失<0.3% 作为当前协议的验收。局部阈值、任务允许退化、坏漏判上限与延迟收益标准由开发数据及人类指南事先冻结，并同时记录其理由；没有数值容忍度就报告完整质量—延迟曲线，不自行宣布“噪声内无损”。

在冻结确认集上统计：skip覆盖率、unsafe-skip次数，分别以 skipped 决策数与全部合格决策数为分母的条件风险/总体发生率、按文档聚合的尾部误差、逐任务真实质量、长生成失败，以及所有 gate/维护/重建开销。有限样本零失败不等于零风险；若做区间估计，以独立文档为单位，说明选择与多重比较影响，不把相关 token 数当独立样本数。
