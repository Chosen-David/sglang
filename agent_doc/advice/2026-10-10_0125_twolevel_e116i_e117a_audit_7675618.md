## 1. 128K arm 契约仍不可区分，新增测试把旧缺口编码为正例

### 位置与违反契约

- `analyze_e119_ruler128k_formal.py:106-120` 仍明示 mavg/aavg 两条 `ARM_CONTRACT` 完全相等。
- 已提交真实 manifest 的 `extra_params` 也完全相同：
  - `results/e119_ruler128k_formal_mavg.json.manifest.json:14-16`；
  - `results/e119_ruler128k_formal_aavg.json.manifest.json:14-16`。
- 新 `test_e119_crossarm_identity.py:12-15,187-190` 特意让 128K fixture 只记录相同 method；`test_N7_treatment_swap:435-448` 却把 mavg 改成 `{far_method=avg, near_method=avg, alpha=beta=gamma=0}`。这个负例能证明“未知完整 treatment 会被拒绝”，但不能证明“两个真实、均只有相同 method 的臂被对调会被拒绝”。

实际运行四组回归均通过：

```text
python3 test_e119_crossarm_identity.py 64k      -> 16/16 PASS
python3 -O test_e119_crossarm_identity.py 64k   -> 16/16 PASS
python3 test_e119_crossarm_identity.py 128k     -> 16/16 PASS
python3 -O test_e119_crossarm_identity.py 128k  -> 16/16 PASS
```

64K 日志 SHA256：`deea2b33d1f13ad61bacfc3c4444f4a8b0fb6bcd29aca8226c3d06a1520dd985`；128K 日志 SHA256：`c8d532025f5c2f7b0a78a560c89a26028275505cd1e79be704563456be7d982c`。普通与 `-O` 输出逐字节相同。

这组通过是新发布协议、快照读取、失败不覆盖 summary 等子项的有效程序证据；它不是 arm↔treatment 单射的证据。目录和 SHA 能证明“某些 bytes 自某个被命名的目录读取且未被改变”，不能证明原模型执行使用的是 minmax/avg 或 avg/avg。

## 2. `TL-E116I-GEN-ROLE-HASH-052`：四角色存在检查不等于四文件内容绑定

`analyze_e119_ruler128k_formal.py:246-254` 声称四规范文件 SHA 与 receipt 逐位一致；实现 `:289-307` 的 `rc_sha` 只有：

```python
rc_sha = {
    "manifest": receipt.get("manifest_sha256"),
    "json": receipt.get("result_sha256"),
}
```

随后循环虽读取所有 `generation_files`，只有 `role in rc_sha` 时才比较哈希。128K 合成 v2 fixture 上的最小反例：先用测试自带 `_to_v2` 构造合法三臂，分别覆盖 mavg generation 内 `result.md` 和 `receipt.json`，不改顶层 receipt，再运行正式 128K analyzer。

```text
md: exit=0; summary_exists=True
receipt: exit=0; summary_exists=True
```

复现脚本 SHA256：`9dddacaa66300aaa5ba8bb1b90fb3b6d0e84f6c92a8b31f16a4b89e1d5628a77`；输出 SHA256：`eb707191b8f23ea7550a5228c1d5e29a847d6979849b6d24efe875d6c6454f32`。

这里不要求 receipt 对自身直接哈希（会产生自引用问题）。可维护的做法是：由顶层不可变入口 receipt 或 generation manifest 显式列出非自引用内容哈希；如果 `md` 和 generation receipt 本来只要求存在，就应把闭包字段和文档改成“json/manifest 内容绑定 + 四角色存在”，不要声称四文件 SHA 已闭合。

## 3. `TL-E117A-OUT-BINDING-053`：显式输出与后处理目标分叉

- `analyze_e117a_mavg_ref.py:132-148` 正确识别 `--out`/`--out=...`，不覆盖用户值；
- `:229-235` 在 `base.main()` 后却丢弃解析后的输出路径，调用 `attach_comparison(out_default(argv))`；
- `out_default` 只区分 `--dry-run`，不解析显式输出。

## 修复和最小重测建议

1. **先保持 128K 结论 provisional**：恢复 mavg/aavg 的不同完整契约，或从不可变运行 config/命令/调度记录引入能证明 far/near/αβγ 的哈希绑定。证据不能恢复时，只保留匿名 TLI 单臂观测，不把目录名当执行配置。
2. 增加真正的 128K 交换负例：交换两臂全部真实 artifact/源目录而不制造不存在的 treatment；在没有可区分 native identity 时应 fail closed 或输出 inconclusive。并显式断言 `ARM_CONTRACT['mavg'] != ARM_CONTRACT['aavg']`。
3. 对 generation 协议明确二选一：为 md/receipt 建立非自引用哈希绑定并加内容篡改负例，或缩窄 `publish_protocol_bound`/文档语义，避免“四文件 SHA”假阳性。
4. 修复 E117a resolved output path，并在普通与 dry-run 下各测 `--out PATH`、`--out=PATH`；保证 comparison 与 patch 自检元数据只注入本次输出。
5. 修复后只重验受影响范围：E119 两档普通/`-O` 全矩阵、md/receipt 内容篡改、真实 mavg/aavg artifact 互换、E117a 三种输出形式。GPU/模型资源可用时再补 E113/E117a 完整运行；不要以本轮 py_compile 或 AST 反例替代模型实测。
