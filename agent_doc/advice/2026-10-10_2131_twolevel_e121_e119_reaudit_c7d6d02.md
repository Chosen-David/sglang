## 075：投影路径的“真实 S”仍是 pad 后宽度

### 代码与违反的契约

- `sparse_attn/indexer/tli_indexer.py:239-256` 先把 `k` pad 到 block 倍数，投影路径又从 `pad_k` 构造 `kp` 与逐 token 的 `k_qat`。
- `tli_indexer.py:688-701` 用 `k_qat.shape[1]` 构造 `score_fine`，所以投影路径的 score 宽度为 `Tpad`。
- `tli_indexer.py:813-825` 的 F5 注释把 `score_fine.shape[-1]` 声明为真实 `S`，实际取到 `Tpad`，据此计算 `mid_len`、`near_len_dyn`、`near_base`。
- `tli_indexer.py:963-969` 又在 padded score 的最后 `sliding_window_size` 个位置强制 SWA。
- `sparse_attn/ops/eager_decoding.py:31-37` 最终把 mask 裁到真实 `eos_k-bos_k`。落在 padding 尾部的强制位被丢弃，并不会保护真实序列尾部。

这违反 S-T017/E64 对 sink/SWA 保护区和真实因果长度分区的契约：`mid=[sink,S-swa)`，near/far 应由真实 `S` 推导，真实最后 `swa` 个 token 必须始终可见。

### 触发条件与最小复现

触发条件：启用 `--tli_proj_basis`，进入 α/β 分区路径，且真实序列长度不整除 block size。纯公式复现输入：

```text
{"S":6145,"alpha":0.125,"bs":64,"sink":128,"swa":128}
input_sha256=60e4630c5c5114be947001145653496d1d42828ebb1b94462e8793f3fbe0c186
real=6145 padded=6208
expected_mid_near_farhi_forced_real=(5889,736,5248,128)
actual_mid_near_farhi_forced_real=(5952,744,5312,65)
```

`farhi` 为 block 对齐后的 far 池上界；最后一项为消费端裁剪后仍落在真实 token 域的 SWA 强制位。该例只有 `65/128` 个真实尾 token 被无条件保护，far 上界右移 64 token，near 动态长度也由 736 变为 744。

### 影响与建议

- 影响所有投影基 HF decode 在非 64 对齐步上的选择；E64f/E66/E76 等历史或后续投影实验可能受影响，应按保存的 argv/receipt 识别，不应仅凭文件名推断。
- 当前 E123 cavg/mavg 若未启用 projection basis，则没有证据表明受本缺陷影响。
- 建议让 `compute_mask` 获得 `cu_seqlens_k_fine` 的真实长度（或在 `score_dict` 显式携带 `valid_length`），先把 padding token 永久 mask 为 `-inf`，再按 `[S-swa:S]` 强制真实 SWA；near/far 只按真实 `S` 计算。
- 最小重测：projection on/off × 共享/per-q-head × `S % 64 = 0..63`；断言 padding 永不入选、真实 SWA 全 1、near/far 池与 SG 的逐行真实长度口径一致。

## 077：NUL pointer 仍穿透四态错误归一

### 代码与复现

`benchmark/RULER/yarn_receipt.py:531-551` 严格 UTF-8 解码后只检查 basename、`.`/`..` 与 `/`；`gen\x00name` 是合法 UTF-8 且通过这些检查。随后 `yarn_receipt.py:552-569` 的路径解析进入 `os.path.realpath`，底层 `lstat` 抛 `ValueError: embedded null character in path`。单格入口 `gen_completion_probe.py:340-352` 与 audit 入口 `:290-300` 都只捕获 `(SystemExit, OSError, UnicodeError)`。

最小输入是逻辑预测旁的 `.tli_gen`，内容 bytes 为 `b"gen\x00name\n"`。真实 CLI（普通 Python）结果：

```text
single_rc=1
single_stdout=''
ValueError: lstat: embedded null character in path

audit_rc=1
audit_stdout=''
ValueError: lstat: embedded null character in path
```

预期：单格输出 `STATE=invalid` 且 `rc=2`；audit 把该格计为 `invalid` 后继续枚举后续格，并最终 `rc=2`。

### 影响与建议

- 不改变有效预测内容，但损坏/恶意 pointer 会再次破坏恢复诊断与完整坏格清单，属于 073 的残余异常边界。
- 在共享 resolver 中、任何文件系统调用之前，拒绝 NUL、控制字符和平台路径分隔符；把路径构造/规范化产生的 `ValueError` 统一转换为带 pointer 路径的 `[GATE-FAIL] SystemExit`。入口补捕 `ValueError` 只能作为最后防线，不能替代共享校验。
- 重测非法 UTF-8、NUL、控制字符、绝对路径、父级路径；audit fixture 应把坏格夹在两个好格之间，并在普通 Python 与 `python -O` 下断言逐格继续。

## 078：dangling symlink 未计为遍历覆盖错误

### 代码与复现

`benchmark/RULER/gen_completion_probe.py:267-280` 只在 `dirnames` 中检测 symlink。对指向不存在目标的目录链接，`os.walk(..., followlinks=False)` 会把它列入 `filenames`，因此 074 的检查完全看不到它。

最小目录只有一个 `linked-cell -> missing-cell` dangling symlink。真实 CLI：

```text
rc=0
AUDIT RESULT: total=0 invalid=0 coverage_errors=0（零 pointer 产物，预检无对象）
stderr=''
```

这违反 074 已建立的 fail-closed 契约：未进入的 symlink 子树或不可达别名必须明确计为 coverage error，不能把“无法覆盖”表述成“零产物”。

### 影响与建议

- 不证明既有结果内容错误，但会使聚合预检产生错误的干净摘要；迁移、清理或挂载变化后尤其容易触发。
- 同时检查 `dirnames` 和 `filenames` 的 symlink，或改用显式 `os.scandir` 分类；dangling symlink 应计 coverage error，并保留“从有效别名根单独审计”的出口。还应覆盖扫描期间目标消失的竞态。
