# 自适应 (α,β,γ) 整合评估：GPT 逐层求解器提案 × E109 实测噪声证据

日期：2026-10-08。作者标识：by_kimi3。
整合对象：
- GPT《逐层参数求解器：数学原理与实验设计》（v1.0，2026-10-07，下称"求解器提案"）及其《子空间设计改进建议》的自适应章节；
- 本席 E109 实测二次分析（《E109_per-task配置偏好配对检验与动态自适应评估_20261008_by_kimi3》，下称"噪声证据"）。

**一句话结论：噪声证据否定的是"任务标签 → 配置"这条轴，不否定 GPT 的逐层求解器（逐层轴、输出误差驱动）；但噪声证据为求解器设计提供了六条必须吸收的修订（R1-R6），其中"配对检验纪律"和"坍塌剪枝"应前置进 P0'/v1 协议。**

## 3. 兼容性判决：否定什么、不否定什么

### 3.1 噪声证据否定的

- **"任务类型 → (α,β,γ)"预测器**：任务→配置的映射在同族内是噪声（t<1.8），且天花板 <1 分。求解器提案本身也未走这条路（其表 key 不含任务标签），两份证据在此一致。

### 3.2 噪声证据不否定的

- **逐层求解器的逐层轴**：GPT 的 Eℓ 由**每层实测输出误差**驱动（校准数据、非任务标签），属于"在线/离线统计量 → 预算"家族——正是噪声证据 §6 判为可行的方向。逐层与逐任务是正交轴，逐任务噪声不蕴含逐层无效。

### 3.3 但噪声证据给求解器提了三个硬问题

1. **敏感度链比提案假设的更长**：E109 配对检验量的是"配置 → 选择 → 36 层复合 → 最终文本"，显示同族配置扰动只影响 5-15% 样本。求解器的 Eℓ 只量单层输出误差——**单层误差下降要穿过 35 个下游层的复合才能变成文本差异**。若单层 oracle 收益（P0' 实测中）本身就小，端到端收益大概率被逐层稀释到噪声区。→ 阶段 1 必须先量这个天花板（见 §5）。
2. **判决纪律**：85-97% tie 的先验意味着"逐层表 vs G*"的端到端差异常隐藏在个位数百分比样本里——**均值差不可判，必须逐样本配对检验**（同 §2 方法），否则会把噪声当收益或把收益当噪声。
3. **(0,0) 现象**：单池退化点在 hotpotqa 超所有分区臂。若配对检验确认为真，说明"分区本身"在部分层/任务上是负收益——求解器候选集若不含每层的单池自由，会系统性错失最优点。GPT 网格只含"一个合法单池配置"（§6.2），不够。

## 4. 对求解器设计的六条修订（R1-R6）

| # | 修订 | 依据 |
|---|---|---|
| **R1** | **坍塌剪枝前置**：候选生成即施加闭式坍塌判定（far_budget=0、γ 悬崖、nt_near > near 池容），命中者不求解直接标记"确定性坍塌" | E109 screen4 快筛名单已用此机制省 ~16h 双卡时间；求解器 336 候选中预计有相当比例可免评估 |
| **R2** | **每层单池自由**：候选集从"一个单池配置"扩为"每层可独立选单池退化（far_method 独占全管线）"，逐层表允许分区/单池混合 | (0,0) hq=57.26 实测现象 |
| **R3** | **配对检验进协议**：Eℓ 目标评估与逐层表 vs G* 的端到端对照，一律逐样本配对（均值差 + 配对 SE + 胜负平计数），显著性门槛预注册 | 噪声证据 §3 方法；GPT §11.3 的配对计时纪律向质量侧对齐 |
| **R4** | **Eℓ→e2e 桥梁检验**：在 dev 集上先测"单层误差差"与"端到端分差"的秩相关（同一批候选、同一批 query），相关不显著则 v1 停止——这是 GPT 自标"待验证"项的可操作化 | §3.3-1 |
| **R5** | **β 网格粗化锚定 .125**：β 网格 {0.125, 0.25} 为主（.875 已被 R1 闭式排除，.5 居间证据弱），把搜索预算让给 α/γ | 噪声证据：β 是唯二稳健信号（.125 好/.875 崩），β 细扫无信息 |
| **R6** | **表 key 增加 input-protocol hash**：R01（q_input 丢首 token）修复前后的校准 trace 不可混用；dense trace 缓存必须绑定 pred.py 协议版本 | 本席 bug 审查 R01；GPT §6.3 缓存契约的自然延伸 |

另有一条**不需要修改**的确认：GPT §6.5"near mass 高但 value 相似 → 加配额无收益"与本席噪声机制互为印证——大多数位置的选择对分区扰动稳健（85-97% tie），正是因为 mass 集中且 value 均匀的层对预算再分配不敏感。这条应写进论文动机段，两份独立证据同向。

## 5. 整合后的分阶段路线

| 阶段 | 内容 | 通过门 | 状态 |
|---|---|---|---|
| **0 数据闸门** | ① E109 收官 + `aavg_a0_b0_g0` 三任务补齐；② (0,0) vs 分区冠军全五任务配对检验 | (0,0) 优势显著 → R2 升优先级；不显著 → 单池只做 R1 剪枝后的普通候选 | 链在跑 |
| **1 天花板** | P0' 预注册脚本（#152/#153 已落袋）量逐层 oracle：固定 dense trace，每层独立取最优配置，量 Σℓ Eℓ 相对 G* 的可压缩量 | 天花板显著（预注册阈值）→ 进 2；否则停在 G* 并写 negative result | 脚本就绪 |
| **2 求解器 v1** | GPT §6.4 粗到细搜索 + 本席 R1-R6 | R3 配对检验下逐层表 > G*（预注册显著性）→ 进 3；否则停 | 设计冻结 |

v2（跨层预算分配）只在 v1 通过后启动——GPT §5.2 的顺序判断本席完全同意，不赘述。

## 6. 与系统侧的衔接（避免纸面收益）

- **kernel 静态宽度**：逐层表意味着不同层可能有不同 (nt_near, far_budget) → SG 端口选择表宽度按层变化。CUDA graph 要求静态形状：v1 查表阶段建议**按表内不同配置数预捕获少量 profile**（或按最大宽度 pad + valid 掩码，哨兵协议已就绪）；该成本计入 §5 阶段 3 的效率对照。
- **taskmd kernel 化未竟**（本席性能分析 P1b）：求解器评估用的应该是 kernel 化后的真实耗时 Tℓ(c)（GPT §5.2 已要求"同硬件实际层耗时"），否则 v2 的预算约束会按错误的成本模型分配。

## 7. 证据边界

- 噪声证据的配对检验覆盖 aavg 族一个切片（β=.125, γ=.375, α∈{.125,.5}，4 任务 n=200）；未覆盖跨 method 族与其他 γ 层；
- (0,0) hq 优势未经配对检验，R2 的优先级以阶段 0 结果为准；
- 求解器提案的评估量 5.5%、校准集 48×6 均为计划值，无实测；
- 本文未执行新 GPU 实验；R1-R6 为设计修订建议，落地需随 P0'/v1 实现一并评审；
- E109 全部分数受 R01 输入协议 quirk 影响（全臂同构，相对比较不受影响；R6 处理协议漂移）。
