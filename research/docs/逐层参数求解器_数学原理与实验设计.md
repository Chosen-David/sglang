# Two-Level Attention 逐层 α/β/γ 轻量求解器：数学原理与实验设计

版本：设计稿 v1.0；核查日期：2026-10-07。  
适用项目：Indexer / Two-Level Attention。  
代码核查基线：`Chosen-David/sglang` 的 `two-level-indexer` 分支，提交 `d995ee9319cbbc523f5ecf36e6da31af6f008bfd`。  
文档性质：数学分析、实现建议与预注册实验方案；没有执行本文提出的 GPU 实验，也没有修改 SGLang。已有结果与待验证预测在文中分别标明。

## 1. 推荐结论与需要证明的贡献

建议保留原来的“方法组合海选 → 帕累托候选 → 完整测试”，在候选阶段增加一个**离线逐层参数求解器**。它为每个模型、每种入围方法组合、每个预注册预算档位生成一张配置表；推理阶段直接查表，不在每个生成 token 上重新求解。

第一版只改变各层的 `αℓ, βℓ, γℓ`，保持每层相同的粗筛块预算 K1、细筛 token 总预算 K2、sink/SWA、索引维数及方法组合。这样能回答一个清楚的问题：**相同方法和资源约束下，逐层配置是否优于最佳统一配置？**

暂不把三个变化一起推出：逐层参数、跨层 token 预算重分配、按注意力质量动态划分任意 near/far 块。后两项分别作为后续扩展，避免第一组结果无法归因。

本文的建议与证据等级如下。

| 主张 | 当前等级 | 必须补上的证据 |
|---|---|---|
| token 重合度和 attention mass 不足以决定输出质量 | 数学反例与恒等式支持 | 在真实模型上检验代理与最终指标的关系 |
| 不同层可能需要不同的 near/far 配置 | 合理研究假设 | 同方法、同预算、独立数据上的固定/逐层对照 |
| 轻量求解器可接近有限网格枚举参考 | 待验证算法目标 | 局部目标 regret、求解耗时与峰值资源 |
| 局部输出误差更低会改善端到端任务 | 待验证；没有一般保证 | 联合运行配置表后的任务质量与效率 |
| 考虑 V / 输出几何本身构成全新贡献 | 不成立的创新表述 | OVAL、CriticalKV 等相关研究已有相近动机；需突出本方法的求解对象与系统差异 |

最值得作为论文主线的是：**在 two-level selector 的真实整数预算和分区约束下，以输出失真为校准目标，低成本求出逐层配置，并在同预算下验证质量—效率收益。** 不能仅以“每层参数不同”或者“mass 更高”作为充分贡献。

## 2. 与当前代码对应：α/β/γ 到底控制什么

### 2.1 核查入口与边界

主要文件见 [R1]：

- `python/sglang/srt/layers/attention/tli/config.py`：运行时配置。
- `python/sglang/srt/layers/attention/tli/indexer.py`：分区、候选预算与选择逻辑。
- `python/sglang/srt/layers/attention/tli/backend.py`：按层创建 indexer 的入口。
- `two-level-attention/sparse_attn/indexer/tli_indexer.py`：实验参考实现。
- `two-level-attention/CODEMAP.md`：历史实验与路径说明。

现有 backend 为不同层创建 indexer，但向其传入同一个 profile。因此，“每层存在一个 indexer 对象”**不等于**“目前已支持每层独立 α/β/γ”。实现新功能时要明确层级配置入口。

当前运行时支持 `avg`、`minmax`；历史实验里出现的 `cluster` 组合不能直接视为当前运行时可用。任何候选组合必须先通过运行时可执行性检查。

### 2.2 分区及预算的真实语义

设当前可见序列长度为 N，块大小 b，sink 长度 s，SWA 长度 w，粗筛预算 K1，最终 token 预算 K2。以下是代码语义的简化记号，**不替代实际掩码、末块处理与候选不足分支**。

双池模式的启用条件为：

\[
\alpha>0\quad\text{且}\quad\beta>0.
\]

启用时，代码由 `max(b, int(α·max(0,N−s−w)))` 产生动态 near 长度，随后转换成块边界；near 区域还要排除最后的 SWA 区域。因此，不能把真实 near token 数直接写成 `αN`。

记 near 区块起点为 u，SWA 区块起点为 v，则概念上：

\[
\text{far blocks}=[\text{sink blocks},u),\qquad
\text{near blocks}=[u,v),
\]

sink 和 SWA 作为强制保留项。块边界和 token 边界并不完全相同，要以运行时返回的有效 token 掩码为准。

粗筛预算近似为：

\[
B_n=\max\{1,\operatorname{round}(K_1\beta)\},\qquad
B_f=\max\{0,K_1-B_n\}.
\]

剩余可分配的中间 token 预算为：

\[
K_{2,\mathrm{mid}}=\max\{0,K_2-s-w_{\mathrm{actual}}\}.
\]

near 的目标细筛配额为：

\[
T_n=\min\{\lfloor B_n b\gamma\rfloor,K_{2,\mathrm{mid}}\},\qquad
T_f=K_{2,\mathrm{mid}}-T_n.
\]

解释：α 控制时间分区边界；β 分配粗筛块名额；γ 将 near 粗筛池容量映射为 near 的细筛 token 配额。它们**不是三个任意连续、相互独立的比例**。

核查版本的配置默认值包括 `b=64, K1=128, K2=1024, SWA=128, sink_blocks=2`。在足够长的序列上，强制项占用 256 个 token，理论中间预算为 768；实际唯一 token 数还需检查去重、候选不足与末块掩码。启用 taskmd 而未覆盖方法时，默认组合是 `far=minmax, near=avg`。运行时默认 α/β 为 0，不能把默认配置误称为双池配置。

当 α 或 β 为 0 时走单池逻辑，near method 不再具有双池实验中的含义。候选不足时还可能改变实际配额；求解器必须调用同一选择逻辑，不能用上述标量公式自行补齐 token。

### 2.3 为什么先优化整数配置而非连续微分

β 的取整、γ 的饱和、α 的块边界量化，都产生平台区。同样的输出集合可能对应许多不同的浮点参数。直接对 α/β/γ 做连续梯度优化，会遇到目标不光滑与大面积零变化区。

建议保存两层表示：

1. 人类可读的 `α, β, γ`，用于配置与论文呈现。
2. 求解器内部的有效边界与整数预算 `(u, Bn, Bf, Tn, Tf)`，用于合法性检查、去重与缓存。

去重需要覆盖校准时使用的所有长度桶；两个配置在一个长度上相同，不代表在所有长度上相同。若方法存在非确定性，还要固定 seed、tie-break 和排序约定。只有真正相同的有效选择过程才能共享结果。

## 3. 数学出发点：选择集合质量由什么决定

### 3.1 从真实注意力输出定义问题

对固定的一层、一条 query 和一个 query head，令已经完成模型位置变换的 query/key 给出完整 logits：

\[
z_i=\frac{q^\top k_i}{\sqrt d},\qquad
p_i=\frac{e^{z_i}}{\sum_j e^{z_j}},\qquad
y=\sum_i p_i v_i.
\]

令 two-level selector 最终选择的**有效唯一 token 集合**为 S。若最后仍对 S 读取完整 K/V，并使用原始 logits 做精确归一化，则：

\[
m_S=\sum_{i\in S}p_i,
\quad
\widehat p_i=\begin{cases}p_i/m_S,&i\in S,\\0,&i\notin S,\end{cases}
\quad
\widehat y=\sum_i\widehat p_i v_i.
\]

前提是 S 非空、可见 logits 有限、使用相同 temperature/位置处理/掩码，且不引入 dropout 等随机扰动。低维索引分数仅用于选 S；若最终 attention 也改变 logits，下面的恒等式不再原样适用。

### 3.2 可复核恒等式：mass 与 value 差异共同决定误差

当 `0<mS<1`，定义保留项与丢弃项的条件均值：

\[
\mu_S=\frac{\sum_{i\in S}p_i v_i}{m_S},\qquad
\mu_{\bar S}=\frac{\sum_{i\notin S}p_i v_i}{1-m_S}.
\]

由 `y=mS·μS+(1−mS)·μbarS` 和 `ŷ=μS`，直接得到：

\[
\boxed{y-\widehat y=(1-m_S)(\mu_{\bar S}-\mu_S).}
\]

这是对固定 Q/K/V 的代数推导，不是本文创造的一条全局模型性能定理。`mS=1` 时误差为 0，无需定义丢弃项均值。

它告诉我们：漏掉多少概率质量，以及漏掉的 value 与保留 value 相差多少，必须一起看。如果所有 value 范数不超过 M，则有一般上界 `||y−ŷ||≤2M(1−mS)`；但实际误差可能比该界小很多。

反例一：`p=(0.99,0.01), v=(0,100)`，只保留第一个 token，mass 为 0.99，输出仍从 1 变成 0。高 mass 不自动代表绝对输出误差小。

反例二：所有 `vi=v0`，无论选择哪一个非空集合，输出都为 `v0`。与原始 top-k 的重合度可以很低，输出误差却为 0。

反例三：质量更高的集合也可能输出误差更大。设 `p=(0.6,0.3,0.1), v=(1,0,4)`，完整输出为 1。只选 token 1，mass 为 0.6、误差为 0；选 token 1、2，mass 为 0.9，输出为 2/3、误差为 1/3。增加保留质量改善一个上界，不保证实际误差单调下降。

因此，top-k recall / overlap 与 mass 可作为诊断指标，不能单独当作子空间选择或预算求解的质量目标，更不能替代最终任务精度。

### 3.3 输出误差是一个半正定几何问题

将 V 写为 `N×dv` 矩阵，令 `δ= p̂−p`。对于单 head 的输出投影块 W，设 `Z=V Wᵀ`，则：

\[
\|W(\widehat y-y)\|_2^2
=\|Z^\top\delta\|_2^2
=\delta^\top C\delta,
\qquad C=ZZ^\top\succeq0.
\]

这个二次型把概率误差按照 value/output 几何加权。因为 `1ᵀδ=0`，给所有 value 加同一个常向量不会改变误差。这里是半正定几何，不要求 C 可逆。

**实现不应构造 N×N 的 C。** 直接计算 selected attention 输出，与 dense 输出做差，再应用实际 W 即可。

多 head 情况必须计算：

\[
\Delta o_\ell=W_{O,\ell}\operatorname{concat}_h
(\widehat y_{\ell,h}-y_{\ell,h}).
\]

不同 head 在 W_O 后可能抵消或放大。把每个 head 的误差分别求平方再相加，通常不等于真实投影后误差。当前 GQA selector 的共享 KV head 分组也必须保留；不能把 Q heads 平均成一个“代表 query”来替代原评分语义。

### 3.4 与 softmax 局部敏感度的关系及限制

对有限小 logit 扰动 e，softmax 的 Jacobian 为：

\[
J(p)=\operatorname{diag}(p)-pp^\top,
\quad
\Delta o\approx W V^\top J(p)e.
\]

对应局部误差近似为 `eᵀ J C J e`。它解释为什么只拟合 K 的重建误差不一定保留输出。

但删除 token 相当于引入硬掩码，并非一般意义上的小有限扰动。第一版求解器应直接评估**实际选择集合的输出误差**，不能把该线性化当作硬删除的精确保证。局部敏感度可以用于初始化或快速筛选，不作为最终验收真值。

## 4. 为什么局部改进仍需端到端检验

固定 dense trace 时，每一层的 Q/K/V 来自 dense 模型。但把整张逐层配置表同时上线后，前面层的扰动会改变后面层输入、query、KV 与选择集合，乃至后续生成 token。

在线性化直觉下，最终状态误差包含：

\[
\Delta h_L\approx\sum_\ell J_{L\leftarrow\ell}\Delta o_\ell.
\]

这里的传播 Jacobian 通常未知，且不同层误差会相互作用。因此，逐层最小化 `||Δoℓ||²` 是可执行代理，**不是最终任务最优解**，也不能推出全局单调收益。

推荐三层验证：

1. **固定 trace 的层内验证**：选择集合、概率、输出误差是否正确；求解器是否接近网格参考。
2. **整表联合验证**：同时应用所有层配置，检查真实前向与生成质量。
3. **独立最终测试**：冻结方法和求解协议，在保留数据与长度档位上测试任务精度、延迟、显存。

如果第 1 层通过而第 2 层失败，可以报告“局部代理改善但端到端收益未成立”。不要据此换测试集、只展示获胜任务或者把配置改称为性能提升。

## 5. 推荐优化问题：先固定资源，再考虑分配资源

### 5.1 第一版：各层同预算的参数配置

对层 ℓ、方法组合 m、固定资源 profile b，定义有限合法候选集合 `Cℓ(m,b)`。其中包含当前已验证的统一配置 G*。

记录每个文档 j 中若干 query 的投影后误差，先在文档内部平均：

\[
e_{\ell,j}(c)=\frac1{|Q_j|}\sum_{q\in Q_j}
\frac{\|\Delta o_{\ell,j,q}(c)\|_2^2}{a_\ell^2+\varepsilon}.
\]

`aℓ` 是仅用校准集 dense 输出计算、对所有候选固定的层尺度，例如 projected attention output 的 RMS。不要对每个 query 用可能接近零的输出范数直接做相对误差；同时报告未归一化绝对误差。

任务与文档按预注册权重平均，避免长文因 query 数多而支配目标。主目标先用均值：

\[
E_\ell(c)=\operatorname{Mean}_{\mathrm{task,doc}}e_{\ell,j}(c),
\qquad
c_\ell^*\in\arg\min_{c\in C_\ell}E_\ell(c).
\]

文档误差 P95 或 CVaR90 作为安全诊断；只有均值目标出现稳定尾部问题时，才在开发集上引入固定权重的鲁棒目标。不能反复调整尾部权重去迎合最终测试。

前四层保持 Full Attention，作为所有稀疏方法一致的协议。若以后研究 dense-prefix 数量，将其作为独立消融，不和逐层求解收益混在一起。

### 5.2 第二版：跨层资源分配

有可靠逐层收益后，再考虑：

\[
\min_{c_\ell\in C_\ell}\sum_\ell w_\ell E_\ell(c_\ell),
\qquad
\sum_\ell T_\ell(c_\ell)\le B.
\]

T 应优先来自相同硬件上的实际层耗时/带宽代理，而非只用 token 数。不同层的固定成本、GQA 布局、kernel 路径可能不同。

可用拉格朗日扫描求候选表：`argminc [wℓEℓ(c)+λTℓ(c)]`；但离散非凸候选的全部帕累托点未必都能通过 λ 扫描得到。需要更严格的离散解时，可将耗时离散化后用 multiple-choice knapsack 动态规划，明确量化误差和不可行预算。

该问题仍是**可分离代理优化**。真实端到端质量并不可加，不应把其解叫作整个模型的全局最优配置。

## 6. 轻量求解器设计

### 6.1 先决定“一张表适用于哪里”

第一版输出表的 key 建议为：

`模型 revision × positional profile × method combination × K1/K2 budget`。

模型的各层参数由少量离线校准样本重新求出。不要直接把 8B 的第 ℓ 层参数复制到 32B 的第 ℓ 层；层数、特征分布和 head 结构不同。

长度先在目标范围的混合校准集上求一张稳健表。如果验证表明跨长度转移差，才增加 2–3 张长度桶表。每次引入桶都会增加存储、校准和控制变量；不能一开始就为每个长度、任务、head、query 都求配置。

### 6.2 可复现的有限参考网格

建议第一份预注册网格为：

```text
alpha: 0.0625, 0.125, 0.25, 0.375, 0.5, 0.625, 0.75, 0.875
beta:  0.125, 0.25, 0.375, 0.5, 0.625, 0.75, 0.875
gamma: 0.125, 0.25, 0.5, 0.625, 0.75, 1.0
```

双池原始候选数为 `8×7×6=336`。额外加入一个合法单池配置，以及 G*（若不已在集合中）。因此至多 338 个原始候选，随后按真实整数分区/预算和长度桶去重。

这只是**指定域内的有限网格参考**，不是覆盖所有浮点参数的最优解。若最优点持续贴边，允许在开发阶段扩展一次网格并记录原因；冻结后不根据测试结果扩展。

### 6.3 缓存与采样：昂贵操作只做一次

校准集建议初始为 48 个独立文档，每文档采 6 个 query，共 288 个 query 位置；该数字是可调整的资源起点，不是有理论保证的样本复杂度。

采样应覆盖中后段 prompt 位置和短 decode 轨迹，避免只看最后一个 prompt query。decode trace 可以用固定 dense greedy continuation 或 teacher forcing 提取，说明它是 dense 分布下的代理；不是在线稀疏模型分布。

优先缓存/复用：

- dense attention 输出、必要的 Q/K/V 块或可重算 trace 句柄。
- 同一层/方法的 coarse 与 refine 排序；仅在排序确实不依赖当前配置时复用。
- 各区域的候选 token 索引及 selected-set hash。
- 同集合的输出误差、mass、重合度、实际读取数。

RoPE 已作用后的 logits 使用模型实际频率与位置配置。不要因索引是低维的就将 `1/√d` 擅自改为低维温度。

按层与 query chunk 流式处理，设置 trace 峰值内存上限，避免同时驻留全部层的完整 QK 矩阵。离线读取完整 logits 的成本要记录；“部署无在线开销”不等于“校准免费”。

### 6.4 推荐首版算法：粗到细有限搜索

第一版不必训练一个参数预测网络。使用两级 query 精度与邻域细化，可解释、可复核，也容易与枚举公平比较。

1. 从全校准集选 12 个分层抽样文档，每文档 3 个 query，形成 36-query 低成本子集。
2. 在 `4 个 α × 3 个 β × 3 个 γ=36` 个 coarse 配置上评估低成本输出目标。建议 α `{.125,.375,.625,.875}`，β `{.25,.5,.75}`，γ `{.25,.625,1}`。
3. 提升其中 6 个候选，在全部 288 query 上评估。保留参数分散的备选，避免全落在同一个平台区。
4. 从提升候选附近的参考网格点中，选最多 24 个尚未评估的合法有效邻居，在 36-query 子集上评估。
5. 再提升最多 4 个邻居到全部 query。无论粗筛结果如何，G* 必须在全部 query 上评估。
6. 从全部 query 已评估的候选中，选 Eℓ 最低的配置；近似平局时优先稳定、容量充足、与 G* 差异较小的候选。

合计上限：60 次低精度候选评估、11 次全精度候选评估/层；同候选、同集合的计算必须去重。

按候选—query 配对数算，上限为 `60×36+11×288=5328/层`；338 点全精度枚举的上限为 `338×288=97344/层`。前者约为后者 5.5%。这仅是**计划的评估数量比例**，不是实测耗时加速；排序、数据搬运、GPU 启动和缓存会改变真实成本。

为了把“搜索方式”与“目标函数”分开，mass 求解器使用同一候选、同一 query、同一提升数量，只改变评分目标。禁止 output 求解器使用更多前向或更多数据后宣称目标更优。

### 6.5 可选初始化，不能写成闭式最优公式

可以用 dense trace 的近端累计质量、value 离散度、near/far 的粗筛候选覆盖率，为 α/β/γ 的初始候选排序。但不存在由“near mass=某个比例”就能唯一推出最优 α/β/γ 的一般公式。

例如，near 高 mass 但 value 极相似时，继续增加 near 配额可能没有明显输出收益；far 低 mass 但 value 差异大时，少量 far token 可能重要。初始化是启发式，最后必须经过输出目标评估与独立验证。

### 6.6 联合表修订只允许在开发数据上进行

若整表上线出现分布偏移，可在开发集上执行至多 1–2 轮坐标修订：固定其他层，只考察目标层的少数候选，或者在当前稀疏轨迹上重新校准。

这需要计入总搜索成本，并与获得同等追加预算的固定配置搜索比较。不能称为全局最优，也不能在最终测试集上反复修订。

## 7. 需要对每一层暴力枚举吗？

**不需要对每一层分别跑一遍完整 LongBench 端到端暴力枚举。** 也不需要证明逐层求解器接近全模型的未知全局最优解。

你需要两个不同的参照：

| 参照 | 解决的问题 | 怎样做 |
|---|---|---|
| 有限网格层内枚举参考 | 轻量求解是否有效 | 固定同一 dense trace，对候选配置回放，计算同一个层内输出目标 |
| 最佳统一配置 G* | 逐层方法是否值得采用 | 所有稀疏层使用同一 α/β/γ，通过相同开发协议选出最优统一配置，再与逐层表联合运行比较 |

8B 上优先选 8 个代表稀疏层：零基编号 `{4,8,12,16,20,24,28,35}`。这些层只是覆盖深度的预注册抽样，并非因为观察到收益后挑出的“好层”。缓存与预算允许时，再扩展为所有 32 个稀疏层的局部枚举；32B 不强制重做全层 oracle。

统一配置 G* 也要有明确搜索协议。建议对各层目标作预注册加权平均，先按与逐层搜索相同的粗到细候选/query 上限生成统一配置 shortlist，然后在开发集联合运行不超过 8 张统一表：包括代理前三名、当前可比的历史配置、单池配置及最多三个尚未重复的邻域候选。按开发质量与资源约束选 G*。这是**该搜索协议下最优的已评估统一配置**，不是所有连续参数的全局最优。给固定赛道不少于逐层赛道的联合开发运行次数，并分别记录完整校准/搜索成本。若预算允许做全网格层内回放，可把各层误差求和得到更强的统一代理参照，但仍不能把它叫作端到端全网格最优。

层内枚举参考定义为：

\[
c_{\ell,\mathrm{enum}}=\arg\min_{c\in C_\ell}E_{\ell,\mathrm{cal}}(c).
\]

如果轻量结果属于同一候选集，校准集上的 regret 为：

\[
R_\ell=E_{\ell,\mathrm{cal}}(c_{\ell,\mathrm{solver}})
-E_{\ell,\mathrm{cal}}(c_{\ell,\mathrm{enum}})\ge0.
\]

G* 在候选集中，则枚举目标必不劣于 G*；这只是训练/校准目标上的集合包含关系，不是独立集或端到端收益保证。

当 `E(G*)−E(enum)` 明显大于测量噪声时，可报告改善捕获比例：

\[
\operatorname{Recovery}_\ell=
\frac{E_\ell(G^*)-E_\ell(c_{\ell,\mathrm{solver}})}
{E_\ell(G^*)-E_\ell(c_{\ell,\mathrm{enum}})}.
\]

如果分母很小，直接报告绝对 regret 与平台区，不展示夸大的百分比。参数数值相似不是核心指标：不同 α/β/γ 可能选择同一个集合，或者目标几乎相同。

校准集选出的 enum 与 solver 配置均冻结后，在独立验证集测误差。若额外在验证/测试集上计算逐样本最佳候选，只能标成 hindsight oracle 诊断，不能作为可部署结果。

## 8. “mass 密集的是 near，其余为 far”应如何处理

你提出的思路有价值，但会把 near/far 从“按位置划分”变成“按内容相关性划分”。建议采用不同名称，防止概念混淆：

- 现有 near/far：由 query 相对位置与块边界定义。
- 扩展 dense/residual pools：由低成本相关性预测产生，可能是非连续块集合。

上线时没有完整 dense attention mass；若先计算全部真实 mass 再路由，就可能抵消 indexer 的节省。必须用现有 coarse summary 或廉价统计估计 pool，并把它的成本、错误分区和 gather 布局成本算进去。

建议第二阶段最小实验：相同 K1/K2 下，比较位置分区、廉价预测的内容分区、真实 mass 的离线 oracle 分区。第三者只能揭示潜力，不能用于线上性能宣称。再加入 value/output 目标，以检验“mass 密集池”是否真的比位置池好。

仅当离线 oracle 有足够潜力、可部署预测器接近它、且总延迟没有抵消收益时，才把动态池作为主方法。第一版逐层求解器不依赖该扩展。

## 9. 模型选择：两项必做，一项有条件扩展

模型规格以官方模型卡为准 [R7–R9]。固定 checkpoint revision、tokenizer、chat template、位置配置与软件版本。

| 模型 | 论文职责 | 必做实验 | 不必做的工作 |
|---|---|---|---|
| **Qwen3-8B** | 主开发模型；完整机制与求解器证据 | 校准、7 任务海选、代表层枚举、全部核心消融、最终 16 任务、RULER、效率 | 不必一開始就跑每个组合的全部测试 |
| **Qwen3-32B** | 同家族规模验证 | 独立轻量校准；最佳固定 vs 逐层；最终 16 任务；RULER；效率 | 不重新铺开所有方法 × 全网格 × 全部消融 |
| **DeepSeek-V2-Lite-Chat** | 可选 MLA / 跨家族 / NoPE+RoPE 结构扩展 | 先验证 MLA 适配；再少量开发对照和冻结后的质量/效率测试 | 未完成适配时不写已支持 MLA，不拿 GQA 路径直接代替 |

Qwen3-8B 官方规格：8.2B、36 层，Q/KV heads 为 32/8；Qwen3-32B：32.8B、64 层，64/8。两者官方原生上下文为 32768，扩展到 131072 需要指定 YaRN 配置。DeepSeek-V2-Lite 的官方规格为总参数 16B、激活参数 2.4B、32K 上下文 [R7–R9]。

Qwen 主协议建议固定 `enable_thinking=false`，采用确定性 greedy decoding，并固定官方任务所要求的输出长度上限。Greedy 是本实验控制随机性与输出成本的选择，不宣称它是官方模型卡推荐的最佳生成策略。所有 baseline 使用同一模式；thinking 模式若追加，单列为扩展，记录思考与答案 token，不与 non-thinking 分数混合。配置使用统一 chat template 与答案后处理，避免模型正确性差异其实来自评测 harness。

这两项主模型不形成“两个不同家族”的证据。MLA 扩展完成后才能同时提供跨家族与混合位置结构证据。若 MLA 适配无法完成、论文又要明确声称跨家族，则另选一个可支持的跨家族 checkpoint，如 Llama-3.1-8B-Instruct，冻结方法后做补充验证；它不是默认追加的第三个完整开发模型。

**MLA 不是 32B 的替代品。** 它证明架构/位置结构可迁移，32B 证明规模可迁移。如果论文中心贡献明确覆盖 MLA，则至少在正文有一张 MLA 主结果表，详细实现和更多分项放附录；如果仅是扩展可行性，正文简述、附录给充分结果。

### 9.1 NoPE / RoPE 的必要审计

不能把向量的“前半维/后半维”直接叫成 RoPE/NoPE。尤其 Qwen 的 rotate-half 配对可能跨向量两半，一个旋转对必须按实际实现确认。

现有默认子空间索引在 D=128 时包含 `[48..63]` 与 `[112..127]`，其语义需要按真实配对解释。参考实现里出现的 `rope/nope` 切片标签不是架构证据。

每个模型在实验前必须记录：`rotary_dim / partial_rotary_factor / inv_freq / scaling / pair layout / position application point`。位置处理类型由模型代码和数据流判定，不由实验文件名判定。

逐层 α/β/γ 的输出失真目标在 NoPE、RoPE、混合位置结构上都可以定义，因为它使用实际 logits 与 V。但这不意味着底层 selector、KV 存储和 kernels 自动兼容。

MLA 必须审计 latent KV、位置分量与 full attention 重建路径；若为了接入而展开完整 K 缓存，应明确这只是正确性基线，不能把其内存/延迟当成原生 MLA 部署表现。NoPE-only selector 消融也不等于测试了一个 NoPE-only 模型。

### 10.1 三套数据必须分开

推荐每任务先用固定的 16 样本做可执行性与明显劣化检查，再用 48 样本的固定子集海选。不是因为每组都必须用 48，而是预先设定相同资源上限，避免胜者得到更多数据。

七任务覆盖六个类别，其中多文档 QA 有两个代表。这不是完整类别内部覆盖；可额外使用 PassageCount 的 16/32 样本作为计数退化警报，最终必须纳入正式计数测试。

LongBench v1 官方完整集合有 21 个任务，包括 14 个英文、5 个中文与2个代码任务 [R10]。常用的英文+代码协议是 **16 个任务**，不能简称为全部 21 任务。

采用官方 prompt、输出长度与评价脚本并冻结版本。报告每任务结果、六类均值及 16 任务宏平均；不要只报一个总数。若追加中文，则分别报告 21 任务协议及语言分项。

### 10.4 RULER 测精度，也测效率

RULER 不只是长序列测速；它用于检测检索、多跳、聚合等长度相关的能力退化。以官方 13 子任务为完整准确率协议 [R11]，并用独立生成 seeds 区分开发与最终样本。

官方仓库当前提示 v1 新流程在 `rulerv1-ns` 分支，主 README 的旧运行步骤已标为 deprecated。实际执行应固定采用的 v1 pipeline 提交与 task configs，不混入 v2，也不把 README 的旧命令直接当成当前可用流程。

原始 13 个 task IDs 为：`niah_single_1/2/3`、`niah_multikey_1/2/3`、`niah_multivalue`、`niah_multiquery`、`vt`、`cwe`、`fwe`、`qa_1`、`qa_2`。来源为官方 `scripts/config_tasks.sh`；迁移新流程时核对名称和参数对应，避免把“8 needle”单任务当作完整 RULER。旧配置的默认样本数为每子任务 500。

为控制成本，建议在开跑前冻结如下样本方案；每个模型内部所有方法必须使用相同输入和样本数：

| 场景 | 长度 | 任务范围与样本 | 主要方法 |
|---|---|---|---|
| 8B 最终原生 | 8K、16K、合法约 32K | 13 项；优先 500/项/长度 | DENSE、G*、L-OUT；Quest/FASA-C 资源允许同范围执行 |
| 32B 规模验证 | 8K、16K、合法约 32K | 13 项；成本受限可预注册 200/项/长度 | DENSE、G*、L-OUT |
| 短长度能力/代码检查 | 4K | 13 项 × 50 开发样本 | DENSE 与当前候选；不代替最终测试 |
| 8B YaRN 扩展 | 64K、合法约 128K | 13 项；预注册 200/项/长度起步 | DENSE、G*、L-OUT |
| MLA 扩展 | 8K、16K、合法约 32K | 13 项；200/项/长度起步 | 原生 MLA DENSE、G*、L-OUT |

使用 200 样本必须写成“覆盖全部 13 子任务的 200-sample 协议”，不能说复现了官方默认 500-sample 全量。少样本区间较宽，效果接近时应按预注册规则补足样本，而非选择性补测获胜方法。32B 的主要外部竞争证据仍由完整 LongBench 与效率表承担；若宣称 RULER 上胜过外部方法，必须补齐它们在同一协议下的结果。

原生 profile 下推荐 4K、8K、16K，及在总 token 限制内合法生成的约 32K 档。32K input 加上 chat wrapper 和输出可能超过 32768，必须按**最终 tokenized prompt + 最大输出预算**检查，必要时调低生成长度并记录实际档位；不能切掉 needle 后仍视为同一个任务。

64K/128K 单独作为 Qwen 的 YaRN 扩展 profile：

- dense 与所有稀疏方法使用相同位置缩放、tokenizer 和最大输出。
- 求解器在相同扩展频率配置下重新校准，或明确测试从原生 profile 直接转移的消融。
- 先报告 dense 的长度能力，再报告相对 dense 的稀疏退化。
- 最大 prompt 由总容量减输出及包装开销确定；不能机械复制别人的 `127.5K` 常数。
- MLA 默认只验证官方原生长度；未经独立位置扩展验证，不追加 128K 宣称。

主表分开原生与扩展结果。超原生测试合理，但它同时检验位置扩展与稀疏选择，不能把 dense 扩展失败归因于逐层求解器。

## 11. 比较对象：内部归因与外部竞争分开

### 11.1 核心内部对照，8B 全做

所有行使用相同方法组合 m、预算与数据；第一步固定 m 为当前最佳可运行组合，之后再比较方法组合的胜者。

| 代号 | 配置方式 | 层内评分 | 目的 |
|---|---|---|---|
| DENSE | Full KV / Full Attention | 无 | 质量锚点与完整 runtime 成本 |
| G* | 所有稀疏层统一 α/β/γ | 开发集端到端选择 | 最强统一配置，主比较对象 |
| L-MASS | 逐层轻量求解 | retained mass | 隔离“逐层”与“输出目标” |
| L-OUT | 逐层轻量求解 | projected output error | 推荐方案 |
| L-ENUM | 代表层有限网格枚举 | 与 L-OUT 相同 | 搜索质量与成本参照；不是主部署基线 |
| L-PERM | 打乱 L-OUT 的层顺序 | 不重新求解 | 检验是否只是参数集合变化而非层匹配 |

L-PERM 用预注册的多个排列 seed，并保持前四层 dense。只有一个排列偶然变差，不能视为普遍层匹配证据。

两种不可混淆的主比较：

1. **同方法比较**：`G*(m)` vs `L-OUT(m)`，证明逐层配置本身的价值。
2. **完整系统比较**：`best_m G*(m)` vs `best_m L-OUT(m)`，在相同外层筛选预算下比较最终系统。

如果统一配置在旧实验里被搜索得不充分，逐层方案可能只是击败一个弱 baseline。G* 必须在当前代码、实际 K1/K2 与位置 profile 下重新确认；不能直接把历史最优参数当作当前最优。

### 11.2 外部方法的推荐最小集合

| 外部对照 | 地位 | 公平性条件 |
|---|---|---|
| **Quest** | 必做，块级粗筛基线 | 同 checkpoint、相同允许读取量/预算口径与同硬件 [R5] |
| **FASA-C** | 必做，FC 子空间 token 选择 | 使用 GPU-resident 版本；同缓存放置与 final attention 口径 [R4] |
| **OVAL** | 建议增加的近期输出感知对照 | 先验证实现兼容；同 page/rank/cache 布局，计入 basis 构造与额外存储 [R6] |
| SparQ / 其他可靠 token selector | 可选一项 | 实现成熟且实验资源允许，不能用少量劣配置凑弱基线 |

论文预算紧张时，最少保留 `DENSE + Quest + FASA-C + G* + L-OUT`。若强调输出感知的新颖性，应优先增加 OVAL 或至少给出机制对照及原因明确的未复现说明。

FASA-M 的 offload 设置应单独比较，不能把 GPU-resident 方法与不同 CPU/GPU 放置策略混在同一速度表。Eviction 类方法如果追加，需说明不可逆删缓存与保留全 KV、按 query 检索的差异。Prefill 稀疏方法也不能直接当作 decode indexer 的同阶段竞争者。

外部方法实际不能精确匹配 K1 时，不强求一个没有对应语义的数字；优先匹配最终读取量和资源，报告各自索引成本与实际 latency—quality 曲线。相同 K2 不等于相同总耗时。

## 12. 方法海选应该怎么改：保留两条赛道

### 12.1 推荐流程

1. **协议审计**：固定代码、checkpoint、位置配置、预算，检查 runtime 支持的 method。
2. **小样本可执行性筛选**：7 任务各 16 个预定样本。排除错误实现与明显退化。
3. **统一配置赛道**：按预注册开发预算搜索每个 method 的 G*(m)。
4. **逐层配置赛道**：仅对 2–3 个合理入围 method，分别运行同一轻量求解协议，得到 L-OUT(m)；不能用一个 method 求的表直接给其他 method 使用。
5. **配对海选**：7 任务各 48 个固定样本，对 G*(m)、L-MASS(m)、L-OUT(m) 做同任务配对比较。
6. **冻结候选**：选择不超过 2 个明确的质量—效率帕累托候选，保存配置/hash/选择规则。
7. **完整测试**：胜者及必需 baselines 测 16 任务、RULER 与效率。不能再根据该阶段分数反复换配置。

这样既保留原计划，也能回答逐层是否超过最佳固定组合。不要只让逐层赛道使用更丰富 method，然后把最终差异全部归因于参数求解器。

### 12.2 预算档位

主实验先固定 `K1=128, K2=1024, b=64, sink=128, SWA=128`，与当前运行时语义核对后执行。质量—效率曲线建议再加 `K2=512,2048`，三档均记录实际唯一 token 数与全量 fallback 频率。

每个档位的逐层表分别校准；先在主档选定方法，再将同一方法带到另外两档轻量校准，避免三档都重复完整 method 海选。若方法本身随预算改变，必须把这部分新增搜索成本计入。

资源不足时，先完成主档完整质量测试，另外两档测相同的精简诊断集与效率；明确完整质量曲线尚缺，不能把精简集曲线写成全量结果。

### 12.3 可计算的工作量上限，而非虚构耗时

若 3 个入围 method、3 张配置表、7 个任务、每任务 48 个样本，则配对海选是 `3×3×7×48=3024` 个 sample-configuration 运行，不含 dense、失败重试与统一配置搜索。

优先复用同一 dense trace，不重复提取相同模型/数据的中间量。GPU 小时与 token 成本要用一次 pilot 实测后估计，本文不提供无硬件依据的“几小时完成”承诺。

## 14. 核心消融的优先级

### 14.1 必做或强烈建议

1. **固定 vs 逐层，同 method 同预算**：最关键的归因。
2. **mass vs output，同求解预算**：检验数学目标是否产生实践价值。
3. **轻量 vs 层内枚举**：regret—耗时曲线。
4. **层参数置换**：检验匹配具体层的重要性。
5. **逐层表联合运行**：不能只展示各层误差的独立下降。
6. **独立长度与任务验证**：至少包含没有直接提示选择规则的新问题、跨结构任务、退化反例。

### 14.2 资源允许再做

- 仅 α 逐层、仅 β 逐层、仅 γ 逐层、三者逐层，其他项固定为 G*。
- V-space 误差 vs W_O 后误差：检查多 head/output 几何是否有实质作用。
- 校准文档数 8/16/32/48；query 位置只取末端 vs 分层采样。
- 一张长度混合表 vs 两张长度桶表。
- 层内输出均值目标 vs 预注册尾部鲁棒目标。
- 单池、双池、near-only/far-only 必须先满足代码边界条件；不能用 β=1 随意代替所有关闭 far 的路径。
- FC-only vs 固定索引维度下的 FC+低秩补偿。作为子空间研究单独做，不与逐层预算收益同时改动。

没有收益的消融也保留。不能因为枚举显示收益小，就删掉它而只强调 solver 很快。

## 15. 质量、效率和统计怎么测

### 15.1 质量指标

- LongBench：官方逐任务指标、16 任务宏平均与六类均值。
- RULER：逐子任务准确率、每个长度的宏平均；dense 与稀疏同样报告。
- 局部代理：projected output MSE、绝对误差、文档尾部、retained mass、top-k overlap、选择集合变化率。
- 可选：独立答案上的 NLL / KL；dense 自生成答案只能作为 distillation/consistency 指标，不能冒充真实答案精度。

同一输入使用配对比较。统计重采样以文档/样本为单位，不能把同文档的数百个 query 当作独立样本。跨任务总体分数按任务分层重采样；说明区间是对哪些样本来源的不确定性估计。

### 15.2 效率指标与控制项

必报 TTFT、decode TPOT、总延迟、吞吐量、峰值 GPU 显存、索引缓存与 workspace；另报离线校准耗时、全量前向次数、query 数、candidate 数与摊销。

固定 GPU 型号/数量、TP/PP、batch、输入长度、输出长度、精度、KV 放置、kernel 路径和编译参数。先用 PP=1 或明确可控设置做方法归因，再以实际部署 TP/PP 做系统验证；不能拿不同并行方式的数字直接作方法加速比。

纯 decode microbenchmark 用相同固定 query/长度轨迹；端到端生成另报实际输出 token 数。EOS 早停、思考长度变化不能被算成 attention kernel 加速。

建议 warmup 至少 3 次，测量 10 次并跨 5 个独立轮次随机化方法顺序；具体次数可由 pilot 调整后冻结。报告中位数及区间。极短负载需要足够重复或 GPU event 聚合，单次计时不能判断 1% 差别。

公平资源有两种口径，分别画图：

1. **同选择预算**：K1/K2 与 actual selected tokens；检查方法质量。
2. **同实际成本**：latency/memory 的帕累托曲线；检查系统价值。

第一口径胜出，不保证第二口径胜出。低秩补偿、OVAL basis 或额外缓存都必须把构造、维护和存储计入总账。

### 15.3 校准摊销

设离线额外成本为 Ccal，每条请求节省时间为 ΔT>0，则简单时间口径下的盈亏平衡请求数为 `ceil(Ccal/ΔT)`。在质量改善但不节省时间时，不应计算虚假的速度摊销。

配置表静态查表通常成本很小，但实际 backend profile 解析、图捕获和 kernel 调度仍需实测。报告冷启动和稳态，避免把预热成本隐藏。

## 16. 预注册验收与停止条件

下列是推荐的**预注册判据**，不是已达到的结果或通用理论阈值。

| 层级 | 通过条件 | 未通过如何处理 |
|---|---|---|
| 数学/代码 | 手算小例与 FP64 回放一致；actual masks、预算、GQA、softmax 语义一致 | 停止质量比较，先修正确性 |
| 轻量搜索 | 独立集 regret 小；校准成本显著低于网格；同时报告无收益平台层 | 扩大少量提升候选或保留负结果；不宣称求解有效 |
| 同方法端到端 | 同预算下相对 G* 有可复现收益，且关键任务无不可接受退化 | 保留知识与分析，不默认部署 |
| 系统 | 同成本帕累托改进，或预注册非劣质量下的延迟收益 | 只报告精度收益，或认定本轮无值得采用的升级 |
| 泛化 | 32B/新任务/新长度的独立结果支持具体范围 | 收窄论文主张，不用局部代理补足 |

数值门槛建议先用 pilot 估计噪声，再冻结。示例：在有明显枚举收益的层上，目标改善捕获比例中位数 ≥90%；求解耗时 ≤枚举的 20%；TPOT 不劣超过 3%；任务非劣界可先按总体 0.5 分与单任务 2 分设计。**这些例值需要在测试前依据噪声和业务容忍度选择**，不应被写成数学保证，也不要在看完结果后移动门槛。

绝对误差和最终任务优先于比例。若 G* 与 enum 几乎无差异，应报告“该协议下逐层优化潜力有限”；求解器接近一个没有收益的 oracle 并不证明方案值得采用。

保留未参与开发的样本清单。测试一旦公开并用于修订，就转为已用测试；下一版需新的保留集或明确只作回归。

第一版只允许 α/β/γ 的逐层覆盖，其他 shape-affecting 参数共享，以减轻图捕获与缓存容量管理风险。动态 gate、层 skip mask 与其他自适应功能在主对照中固定，单独消融。

### 17.3 必要验证用例

- 短序列不足 sink+SWA、空 near、末块不完整、K2 小于强制项、候选不足。
- α=0、β=0 的单池模式；γ 饱和平台；整数边界左右。
- selected tokens 去重与 causal/padding mask；禁止负索引或填充值混入 softmax。
- 共享 KV head、多 query heads、实际 W_O 后输出。
- 小规模随机数据上的 dense/replay/runtime 一致性；FP32/BF16 差异与容差分开。
- 每个模型至少一个真实 forward 的 profile 命中与 full-attention fallback 检查。

K2 小于强制项的配置应由约束层拒绝，或完整记录 runtime 明确的退化规则；不要静默声称它满足总预算。

这些是核查提交中的历史结果，不是本轮重新运行 [R2–R3]。

| 记录 | 能说明什么 | 不能说明什么 |
|---|---|---|
| E98 | 已存在方法/参数搜索与 13 任务结果 | 不等于当前运行时全 16 任务复现；不同预算协议不可直接合并 |
| E99 predictor probe | 该小样本配置集合中，mass 代理与 e2e 排名对应很弱 | 不证明所有 mass 代理无效，也不证明输出目标一定更好 |
| E79a per-layer oracle | 特定 trace、预算和候选域中，逐层 mass 提升很小 | 不是整模型 e2e oracle；不是逐层输出优化收益的上界 |

E99 的 13-arm 记录里，mass_total 与 e2e 平均分的 Spearman 约为 0.166，p≈0.589；去重后 10-arm 约为 0.2，p≈0.580。样本少且存在预算口径问题，应用于提出新实验，而非宣布统计定论。

E79a 的记录来自 8 个样本与抽样层，mean mass coverage gain 为约 0.0007875；脚本里的 BP/SWA 等设置也不同于本文主档运行时默认值。它支持“应先检查潜力、不要预设逐层一定大幅提升”，不能冒充 e2e 最优差值。

第一轮实现时先重放当前真实代码和预算，检查旧结果是否具有可比性；不得仅凭历史文件名 `oracle` 赋予它全局最优含义。

## 19. 最新研究如何影响创新定位

### 19.1 FASA：子空间质量与逐层配置是不同轴

FASA 使用少量 frequency components 进行 token 重要性预测，然后对选中 token 执行完整 attention；它的离线 FC 选择和其他兼容扩展需按原文理解 [R4]。不能把它简化成“所有层选同样的 FC”，也不能仅凭 overlap 不是 e2e 目标就推断其已报告结果有误。

本方案的机会是：在 FC 或其他 selector 固定后，优化**每层分区与两级预算配置**，以实际输出失真检查代理不足。FC+低秩补偿属于另一个正交轴，应先固定一种索引再做参数实验。

### 19.2 OVAL：输出感知已是明确相关方向

OVAL v1 于 2026-10-05 提交，核查时为 arXiv 预印本，未核实正式接收。它基于 K/V 的联合几何构造 page-local basis，结合输出敏感度和 key fidelity，并讨论独立校准；其谱目标涉及特定局部近似/查询假设 [R6]。

本文不照搬其 page basis，而是对真实硬选择集合直接计算 projected output distortion，求解 α/β/γ 的离散配置。两者可以组合，但“首次考虑输出/value”不应作为本文创新。

### 19.3 动态层预算研究的边界

DynamicKV 研究层级缓存分配；FlexPrefill 研究 prefill 的动态稀疏预算 [R12–R13]。它们提示层间差异值得探索，但任务阶段、是否永久删缓存和预算对象不同。

推荐强调自己的交集：**two-level decode retrieval + 实际整数分区/容量约束 + 输出误差校准 + 轻量求解成本 + 整表端到端验证**。先检查相关工作的精确覆盖范围，再确定贡献措辞。

| 顺序 | 交付物 | 完成标志 |
|---|---|---|
| P0 | 代码/profile/模型/数据审计表 | αβγ、预算、位置、GQA/MLA 路径明确 |
| P1 | selector 回放与小例验证 | 数学反例、边界、runtime 对齐通过 |
| P2 | 8B trace 与统一配置 G* | manifests 冻结，旧结果预算已核对 |
| P3 | 输出目标与轻量求解器 | 相同数据/候选协议可重复 |
| P4 | 8 层枚举 + 独立局部验证 | regret、耗时、平台层留档 |
| P5 | 7 任务配对海选 | 同方法与完整系统两项比较齐全 |
| P6 | 8B 完整冻结测试 | 16 任务、RULER、效率、显存 |
| P7 | 32B 独立校准与冻结验证 | 不重复全部开发矩阵 |
| P8 | 可选 MLA | 先正确性和原生存储，再质量/效率 |

每轮记录至少包括：model/revision、source commit、profile hash、数据 hash 与用途、method、逐层参数表、整数预算、实际 selected tokens、校准 query/candidate 数、GPU 时间、峰值内存、生成 token 数、测试是否已用、局部目标与 e2e 差异、失败与下一步。

实验的正确结束方式可以是：“输出误差代理通过，但端到端没有稳定优于最佳固定配置；保留分析与校准工具，当前不采用逐层部署。” 负结果能避免把复杂性永久接入系统，也属于有用的能力建设。
